## 1. 이 앱은 무엇인가

- OpenCode v2의 개인용 포크입니다. 에이전트가 이 PC(또는 SSH로 연결한 Linux 호스트)에서 파일을 읽고 고치고 명령을 실행합니다.
- **한 세션을 여러 계정·프로바이더가 이어서 씁니다.** ChatGPT 구독, OpenAI·Anthropic·DeepSeek·xAI·OpenRouter API 키, OpenAI 호환 서버를 계정으로 등록하고, 세션마다 `모델 @ 계정`을 고릅니다.
- **전환할 때 비용을 먼저 보여 줍니다.** 프롬프트 캐시는 계정·모델마다 따로라서 전환하면 문맥을 다시 읽습니다. 앱은 그 비용을 추정해 보이고, 싼 시점(압축 직후, 캐시가 식은 뒤)을 고를 수 있게 합니다.
- **계정별 한도를 한곳에서 봅니다.** 5시간·주간 한도, 지출, 잔액과 그 값이 실측인지 추정인지를 표시합니다.
- 구성
  - **서비스**: `opencode.exe`가 사용자 세션의 백그라운드 프로세스로 `127.0.0.1:28538`에서 돕니다. 창을 닫아도 턴은 계속됩니다.
  - **데스크톱 앱**: 서비스에 붙는 창입니다. 서비스가 없으면 launcher로 띄웁니다.
  - **launcher `own`**: 서비스를 띄우는 유일한 명령입니다. 환경 변수를 정리하고(프로바이더 키 변수는 서비스에 넘기지 않음) 설정 파일을 씁니다.
- 모든 리스너는 loopback(`127.0.0.1`)에만 열립니다. LAN이나 인터넷에 여는 설정은 없습니다.
- upstream OpenCode 설치본과 나란히 둘 수 있습니다. 채널 `own`이라 DB(`opencode-own.db`), 포트, 등록 파일, 설정 폴더, 데스크톱 앱 id가 모두 다릅니다.

## 2. 설치

설치, 업데이트, 제거는 **설치 파일 하나로 한 번에** 합니다. 설치 파일(`own-desktop-<버전>-win-x64.exe`)에는 데스크톱 앱과 서비스(`opencode.exe`, 화면 파일, 플러그인, SSH 호스트용 번들, launcher)가 함께 들어 있습니다. 설치 파일이 서비스 부분은 launcher(`own.ps1 install`)에 맡기므로, 손으로 할 때(2.6)도 절차는 같습니다.

### 2.1 준비

- Windows 11 x64, Windows PowerShell 5.1 이상(기본 포함), Microsoft Edge(브라우저 폴백용).
- SSH 원격을 쓰려면 Windows의 선택적 기능 `OpenSSH Client`(`C:\Windows\System32\OpenSSH\ssh.exe`, 8.4 이상).
- 빌드 산출물. 저장소(`D:\own-open-code`, 경로에 `#`이 없어야 함)에서 한 번에 만듭니다. Bun 1.4.4(루트 `package.json`의 `packageManager`)와 Rust(cargo)가 필요하고, 첫 빌드는 Electron(약 151 MB)과 Linux용 네이티브 패키지를 받습니다.
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File own\scripts\build-desktop.ps1 -Version 2.0.18-own.3 -Remote
  ```
  결과는 `own\.out\build\2.0.18-own.3\`에 있습니다(크기는 2026-09-28의 `own.2` 빌드 기준, `own.3`도 거의 같습니다).

  | 경로 | 크기 | 무엇 |
  |---|---|---|
  | `desktop\own-desktop-2.0.18-own.3-win-x64.exe` | 약 345 MB | **설치 파일**(서명 없음). 데스크톱 앱과 아래 `app\`·`bin\`이 모두 들어 있습니다. sha256은 `manifest.json`의 `desktop.installer_sha256` |
  | `app\` | 388 MB (724개 파일) | 서비스 payload: `opencode.exe`(187 MB, 서비스·CLI), `web\`(26 MB, 화면), `plugins\own-accounts`·`own-remote`·`own-telemetry`, `remote\linux-x64-baseline.tar.gz`(87 MB)·`linux-arm64.tar.gz`(86 MB)·`manifest.json`(SSH 호스트용), `own-vault.exe`(키 저장소 helper), `templates\`, `manifest.json`(파일 해시) |
  | `bin\own.cmd`, `bin\own.ps1` | 약 90 KB | launcher 0.4.0. `bin\own.cmd install`로 손으로 설치할 때 씁니다(2.6) |
  | `manifest.json`, `desktop-build.json` | – | 버전, build id, 파일 해시, 설치 파일 크기·검사 결과 |

  - `-Remote` 없이 빌드하면 SSH 호스트용 번들(약 172 MB, 이미 gzip이라 더 줄지 않음)이 빠져 설치 파일이 175 MB 안팎이 됩니다. 그 설치본으로는 SSH 호스트를 추가할 수 없습니다.
  - `desktop\win-unpacked\`는 시험용 압축 해제본이라 설치에 쓰지 않습니다.

### 2.2 설치 (한 번에)

1. `own\.out\build\2.0.18-own.3\desktop\own-desktop-2.0.18-own.3-win-x64.exe`를 실행합니다. 묻는 것 없이 현재 사용자에게 설치됩니다(관리자 권한 없음). 1분 안팎 걸립니다.
2. 끝나면 `Own OpenCode` 창이 열리고, 앱이 서비스를 시작합니다(3장).

설치 파일이 하는 일:

- 데스크톱 앱을 `%LOCALAPPDATA%\Programs\own-desktop\`에 두고 시작 메뉴에 `Own OpenCode`를 만듭니다.
- 서비스를 `%LOCALAPPDATA%\own-open-code\app\2.0.18-own.3\`에 두고, 설치된 버전을 **버전 포인터 파일 `app\current.json`**에 적습니다(`{"version":"2.0.18-own.3","path":"…","previous":…}`, 임시 파일에 쓰고 디스크에 내린 뒤 이름을 바꿔 한 번에 바뀜). 앱, launcher, 플러그인은 모두 이 파일에서 버전 폴더를 찾습니다. **junction(`app\current`)은 쓰지 않습니다**: 일부 Windows 11에서는 `%LOCALAPPDATA%` 아래 junction을 통해 파일을 열 수 없기 때문입니다. 들어가기 전에 `manifest.json`의 해시로 파일을 확인합니다.
- launcher를 `%LOCALAPPDATA%\own-open-code\bin\`(`own.cmd`, `own.ps1`)에 두고 이 폴더를 **사용자 PATH**에 넣습니다. 새로 연 PowerShell 창부터 `own`이 됩니다. `opencode.exe`는 PATH에 두지 않습니다. 진입점은 `own`뿐입니다.
- `%USERPROFILE%\.config\own-open-code\opencode.jsonc`가 없으면 만듭니다(플러그인 3개, 기본 권한, 자동 업데이트 끔). 있으면 **own 플러그인 항목만** 새 버전 폴더(`…/own-open-code/app/2.0.18-own.3/plugins/own-accounts` 등)로 고치고 나머지(다른 플러그인, 주석, 순서, 서식)는 그대로 둡니다. 테마는 앱 기본값(어두운 테마)을 그대로 씁니다.
- 한 일을 `%LOCALAPPDATA%\own-open-code\install.log`에 적습니다. 설치 파일 쪽 기록(실행한 명령, 쓴 PowerShell, 종료 코드)은 `%TEMP%\own-installer.log`에도 남습니다.

확인: 새 PowerShell 창에서 `own version` → `own launcher 0.4.0`과 `opencode 2.0.18-own.3 (…\app\2.0.18-own.3\opencode.exe)`. `own status`의 `installed`는 `2.0.18-own.3`, `app_source`는 `pointer`입니다.

- **서명하지 않은 설치 파일입니다.** 이 PC에서 빌드한 파일은 보통 경고가 없습니다. 다른 PC에서 복사하거나 내려받은 파일이면 `Windows의 PC 보호`(SmartScreen) 창이 뜹니다. 파일 출처를 확인한 뒤 `추가 정보` → `실행`을 누릅니다.
- **여유 공간.** 설치하는 동안 약 1.5 GB가 필요합니다(임시 압축 해제 포함). 설치 뒤에는 앱 약 450 MB, 서비스 버전 하나당 약 390 MB입니다.
- 서비스 설치가 실패하면 설치 파일이 `own-open-code 서비스를 설치하지 못했습니다(종료 코드 …)` 창으로 알립니다. 데스크톱 앱은 설치됩니다. 원인은 `install.log`와 `%TEMP%\own-installer.log`에 있고, 고친 뒤 설치 파일을 다시 실행합니다.
- 첫 실행은 Defender 검사 때문에 느릴 수 있습니다.
- 앱 자동 업데이트, `opencode://` 같은 URL 프로토콜 등록은 없습니다.
- 조용히 설치: `Start-Process -Wait .\own-desktop-2.0.18-own.3-win-x64.exe -ArgumentList '/S'`. **`-Wait`가 필요합니다**: 설치 파일은 창 프로그램이라 PowerShell·cmd에서 `/S`로 실행하면 곧바로 돌아오고, 서비스 부분은 앱 파일(약 400 MB)을 다 푼 뒤 마지막에(보통 30초~1분 뒤) 돕니다. 기다리지 않고 바로 보면 `OWN_HOME`이 아직 없고 `resources\own-payload`가 그대로인 것이 정상입니다.
  - 종료 코드: 0 성공, 4 서비스가 세션을 실행 중이라 바꾸지 않음(`/S --own-force`는 세션을 중단하고 진행), 서비스 부분이 실패하면 launcher의 종료 코드(1 등, 데스크톱 앱은 설치됨). `(Start-Process -Wait -PassThru …).ExitCode`로 봅니다.

### 2.3 새 버전으로 바꾸기

**새 버전의 설치 파일을 실행합니다.** 따로 할 일은 없습니다. 설치 파일은 이 순서로 합니다.

1. 서비스가 다른 버전으로 돌고 있고 **실행 중인 세션이 있으면 먼저 묻습니다**: `Own OpenCode 서비스에서 세션이 실행 중입니다. … 지금 서비스를 멈추고 업데이트할까요?` `아니요`를 누르면 아무것도 바꾸지 않고 끝납니다. 턴이 끝난 뒤 다시 실행합니다.
2. 열려 있는 데스크톱 앱을 닫고 새 앱으로 바꿉니다.
3. 서비스를 멈춥니다.
4. 세션 DB `%USERPROFILE%\.local\share\opencode\opencode-own.db`(있으면 `-wal`, `-shm`도)를 `%LOCALAPPDATA%\own-open-code\backup\opencode-own.<이전 버전>.<시각>.db`로 백업합니다. DB 이전은 되돌릴 수 없다고 보고 버전을 바꿀 때마다 백업합니다(최근 5개만 남김).
5. 새 `app\<새 버전>`을 두고 `app\current.json`이 새 버전을 가리키게 한 뒤, `opencode.jsonc`의 own 플러그인 항목을 새 버전 폴더로 고칩니다. **이전 버전 폴더는 되돌리기용으로 남깁니다**(2.4). 그보다 오래된 버전 폴더는 지웁니다. 이전 launcher가 만든 `app\current` junction이 있으면 따라 들어가지 않고 링크만 지웁니다(2.7).
6. launcher를 새 것으로 바꿉니다.
7. 서비스가 돌고 있었다면 새 버전으로 다시 시작합니다(새 버전의 `opencode.exe`와 플러그인). **새 서비스가 뜨지 않으면** `app\current.json`, 플러그인 항목, DB를 되돌리고 이전 버전을 다시 띄운 뒤 실패를 알립니다.
8. 새 앱을 엽니다.

- 파일을 푸는 동안 세션이 새로 시작되면 한 번 더 묻습니다. 이때 `아니요`면 앱만 새 버전이 되고 서비스는 이전 버전으로 남습니다. 앱이 "셸과 UI 버전이 맞지 않습니다"를 보이면(그동안은 `브라우저로 열기`) 세션이 끝난 뒤 설치 파일을 다시 실행합니다.
- 같은 버전의 설치 파일을 다시 실행하면 앱만 다시 설치하고 서비스는 그대로 둡니다(`install.log`에 `already installed`).
- 새 버전에 이전 버전에 없던 own 플러그인이 있으면(예: 컴퓨터 사용 `own-computer-use`) 5번에서 `opencode.jsonc`에 그 항목을 자동으로 넣습니다. 컴퓨터 사용은 세션마다 PC에서 켜야 동작하지만, 설정 파일이나 마크다운으로 직접 정의한 에이전트의 도구 목록에는 켜기 전에도 컴퓨터 도구가 보입니다(호출은 모두 거부됩니다, 01 §10.2). 원하지 않으면 그 항목을 지우고 `own restart`를 실행합니다. 지운 항목은 다음 업데이트에서도 다시 넣지 않습니다.
- SSH 호스트는 `업데이트 필요`가 되고, 호스트마다 업데이트합니다(10.5).
- **Claude 구독 플러그인**은 앱에 들어 있어 앱과 함께 바뀝니다(4.4). 플러그인을 직접 설치해 쓰던 이전 버전(launcher 0.5.0 이하)에서 업데이트하면, launcher(`own install`/`update`)가 `opencode.jsonc`의 `thirdparty\claude-auth` 항목을 앱에 든 폴더로 저절로 바꾸고, 업데이트가 성공한 뒤 `%LOCALAPPDATA%\own-open-code\thirdparty\claude-auth\`의 예전 npm 설치 파일(`node_modules`, `package.json`, `package-lock.json`, `server.js`, `own-patch.json`, `own-patch-original`, 약 130 MB)을 지웁니다. Claude 계정 목록(`claude-accounts.json`), 계정별 상태(`claude-auth-state\`), 계정 로그인 폴더(`%LOCALAPPDATA%\own-open-code\claude-accounts\…`), 연결한 로그인은 그대로이므로 다시 로그인하지 않아도 됩니다. 예전 동의도 더는 필요 없습니다. 그 뒤 이전 버전으로 되돌리면 그 버전의 Claude 플러그인 설치가 다시 필요합니다.

### 2.4 되돌리기 (`own rollback`)

- `own rollback`: `app\current.json`(과 `opencode.jsonc`의 own 플러그인 항목)을 직전 버전으로 되돌립니다. 서비스가 돌고 있었으면 멈추고(세션이 있으면 묻습니다) 이전 버전으로 다시 시작합니다. 한 번 더 `own rollback`을 하면 다시 새 버전입니다. 열려 있는 앱 창은 다시 로드할 때 되돌린 버전의 화면을 씁니다.
- DB는 기본으로 그대로 씁니다. 되돌리기 전에 현재 DB를 `backup\`에 백업합니다.
- 이전 버전이 새 버전이 옮긴 DB를 열지 못하면(서비스가 뜨지 않음) 새 버전으로 돌아간 뒤 `own rollback --restore-db`: 업데이트 때 만든 백업으로 DB를 되돌립니다. **그 뒤에 만든 세션은 사라집니다**(사라지는 DB도 먼저 백업합니다).
- `own rollback --to <버전>`: `app\` 아래 남아 있는 다른 버전으로.
- 데스크톱 앱은 되돌리지 않습니다. 두 버전의 셸 계약(rpcHash)이 다르면 앱이 불일치 화면을 보이므로, 그때는 이전 버전의 설치 파일을 실행합니다(서비스도 그 버전이 되고, DB는 다시 백업합니다).

### 2.6 손으로 설치하기 (대체 경로)

설치 파일을 쓸 수 없을 때(데스크톱 앱 없이 서비스만, 또는 설치 파일이 막힐 때) 같은 절차를 launcher로 직접 합니다.

```powershell
# 빌드 폴더의 launcher로 그 빌드를 설치 (설치 파일이 하는 서비스 부분과 같음)
D:\own-open-code\own\.out\build\2.0.18-own.3\bin\own.cmd install
# 이후 버전: 설치된 own으로, 새 빌드 폴더를 가리켜
own update --from D:\own-open-code\own\.out\build\2.0.18-own.4
```

- `own install`과 `own update`는 같은 명령입니다. `--from`에는 `app\`와 `bin\`이 있는 빌드 폴더를 줍니다(빌드 폴더의 `bin\own.cmd`로 실행하면 생략). 새 버전의 launcher가 들어 있으면 그 launcher가 일을 넘겨받습니다.
- 세션이 실행 중이면 콘솔에서 묻습니다. `--force`는 묻지 않고 멈춥니다. `--no-start`는 설치 뒤 서비스를 다시 시작하지 않고, `--no-path`는 PATH를 건드리지 않습니다. `--json`은 결과를 JSON으로 출력합니다.
- 데스크톱 앱은 설치하지 않습니다. 앱 없이 쓰려면 `own open --browser`(브라우저 폴백)입니다.

launcher도 쓸 수 없을 때의 마지막 방법(DB 백업과 되돌리기 없음, 서비스를 먼저 `own stop`):

```powershell
$ver   = '2.0.18-own.3'
$build = "D:\own-open-code\own\.out\build\$ver"
$own   = Join-Path $env:LOCALAPPDATA 'own-open-code'
New-Item -ItemType Directory -Force -Path "$own\app", "$own\bin" | Out-Null
Copy-Item "$build\app" "$own\app\$ver" -Recurse       # $own\app\$ver가 이미 있으면 먼저 지웁니다
Copy-Item "$build\bin\*" "$own\bin" -Force
# 버전 포인터 (junction은 만들지 않습니다)
$pointer = [ordered]@{ schema = 1; version = $ver; path = "$own\app\$ver"; previous = $null; updatedAt = (Get-Date).ToUniversalTime().ToString('o') }
[IO.File]::WriteAllText("$own\app\current.json.tmp", ($pointer | ConvertTo-Json), (New-Object Text.UTF8Encoding $false))
Move-Item -Force "$own\app\current.json.tmp" "$own\app\current.json"
# 이전 launcher가 만든 app\current junction이 있으면 링크만 지웁니다(따라 들어가지 않음)
if ((Get-Item "$own\app\current" -Force -ErrorAction SilentlyContinue).LinkType) { [IO.Directory]::Delete("$own\app\current") }
# own 명령을 PATH에 (REG_EXPAND_SZ를 유지, 새 PowerShell 창부터 적용)
$key = [Microsoft.Win32.Registry]::CurrentUser.CreateSubKey('Environment')
$path = $key.GetValue('Path', '', 'DoNotExpandEnvironmentNames')
if (($path -split ';') -notcontains "$own\bin") { $key.SetValue('Path', ($path.TrimEnd(';') + ";$own\bin").TrimStart(';'), 'ExpandString') }
$key.Close()
```

- 그다음 `own start`를 한 번 실행하면 launcher가 `opencode.jsonc`의 own 플러그인 항목을 `app/<버전>/plugins/…`로 맞춥니다(서비스가 멈춰 있을 때만 고칩니다).
- junction을 지울 때는 `[IO.Directory]::Delete(<경로>)`나 `cmd /c rmdir <경로>`만 씁니다. `Remove-Item -Recurse`는 junction 대상 폴더의 내용까지 지울 수 있습니다.

### 2.7 "설치되지 않았습니다"가 뜰 때: Claude 앱 안에서 설치한 경우, `app\current` junction

Claude 데스크톱 앱은 MSIX 패키지 앱이라, 그 앱의 **터미널이나 에이전트가 실행한 프로그램이 `%LOCALAPPDATA%`에 새로 쓰는 파일은 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\…`로 옮겨지고, 그 앱의 프로세스에게만 보입니다.** `2.0.18-own.2` 설치 파일을 그렇게 실행하면 서비스(OWN_HOME)가 그 사본에만 생깁니다. 시작 메뉴의 앱, 탐색기, 일반 PowerShell에서는 `%LOCALAPPDATA%\own-open-code`가 없으므로 앱이 `Own OpenCode가 설치되지 않았어요`를 보이고, 설치 파일을 `/S`로 돌린 쪽에서는 "서비스 설치가 안 됐다"로 보입니다. 그 안에서 만든 `app\current` junction은 실제로는 없는 경로를 가리키므로 앱 안에서도 `cmd /c dir …\app\current`가 `지정된 경로를 찾을 수 없습니다`였습니다(PowerShell의 `Test-Path`는 속성만 보므로 `True`).

확인(일반 PowerShell 창에서): `Test-Path $env:LOCALAPPDATA\own-open-code`가 `False`이고 `Test-Path $env:LOCALAPPDATA\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\own-open-code`가 `True`면 이 경우입니다. `own status`(0.4.0)는 `container_copies`에 그 사본을 보입니다.

**할 일: `2.0.18-own.3` 설치 파일을 탐색기에서 두 번 눌러 실행합니다.** Claude 앱 밖에서 돌므로 서비스가 진짜 `%LOCALAPPDATA%\own-open-code`에 새로 설치되고(데이터가 없으면 처음 설치와 같음), 이미 있는 `opencode.jsonc`(`%USERPROFILE%\.config`는 옮겨지지 않았으므로 진짜 파일)의 `…/app/current/plugins/…` 항목은 새 버전 폴더로 고쳐집니다. Claude 앱 안에서 실행하면 새 설치 파일은 `이 설치 파일이 다른 앱… 안에서 실행되었습니다` 창을 띄우고 아무것도 바꾸지 않습니다(`/S`면 종료 코드 5, `%TEMP%\own-installer.log`). 앱 사본(`…\LocalCache\Local\own-open-code`)은 쓰이지 않으므로, 확인한 뒤 일반 탐색기에서 지워도 됩니다(그 안에서 계정을 추가했다면 그 계정은 새 설치에 없습니다. 다시 추가합니다).

앱 밖에서 설치한 `2.0.18-own.2`(junction이 정상)도 `own.3` 설치 파일로 옮겨집니다. 새 launcher(0.4.0)가:

1. junction을 **따라 들어가지 않고** 링크 자체에서 대상(`app\2.0.18-own.2`)만 읽어 설치된 버전을 알아냅니다. 서비스가 돌고 있으면(세션이 있으면 묻고) 그 버전의 `opencode.exe`로 멈춥니다.
2. DB를 백업하고 `app\2.0.18-own.3`을 둔 뒤 `app\current.json`을 씁니다(`previous`는 `2.0.18-own.2`).
3. `app\current` junction을 **링크만** 지웁니다(깨졌든 아니든. `app\2.0.18-own.2` 폴더는 되돌리기용으로 남습니다).
4. `opencode.jsonc`의 `…/app/current/plugins/own-accounts` 같은 항목을 `…/app/2.0.18-own.3/plugins/…`로 고칩니다. 직접 넣은 다른 플러그인과 주석은 그대로입니다(launcher 0.4.0 당시 Claude 슬롯 `thirdparty\claude-auth`도 그대로였습니다. launcher 0.6.0부터는 Claude 구독 플러그인이 앱에 들어 있어, 그 항목 `…/app/<버전>/plugins/claude-auth`도 own 항목처럼 launcher가 고칩니다. 4.4).
5. 서비스가 돌고 있었으면 새 버전으로 다시 시작합니다. 아니면 앱을 열 때 앱이 시작합니다.

확인: `own status`에서 `installed 2.0.18-own.3`, `app_source pointer`, `exe …\app\2.0.18-own.3\opencode.exe`. `own rollback`은 `2.0.18-own.2` 폴더로 돌아가며, 이때도 junction을 다시 만들지 않습니다(포인터만 바꿉니다).

## 3. 처음 실행

1. 시작 메뉴에서 `Own OpenCode`를 엽니다. 서비스가 없으면 앱이 launcher(`own.ps1 start`)를 실행하고 `OpenCode 서비스를 시작하는 중입니다… (own start)`를 보입니다.
   - 첫 기동 때 launcher가 `opencode.jsonc`와 `service-own.json`(임의 비밀번호, `127.0.0.1:28538`)을 만듭니다.
   - 셸 환경 변수의 프로바이더 키(`OPENAI_API_KEY`, `ANTHROPIC_*`, `DEEPSEEK_API_KEY` 등)는 서비스에 넘기지 않습니다. 이름만 경고로 출력하고 값은 보이지 않습니다. 키는 앱 안에서 계정으로 추가합니다.
2. `첫 계정을 추가하세요` → `계정 추가`(4장).
3. `폴더 열기…`(`Ctrl+O`)로 프로젝트 폴더를 고르고 `이 폴더에서 새 세션`.
4. 입력창의 `모델 @ 계정 고르기`로 조합을 고르고, 헤더의 승인 모드(기본 `묻기`)를 확인한 뒤 메시지를 보냅니다.

- **창을 닫아도 서비스와 진행 중인 턴은 계속됩니다.** 다시 열면 결과가 그대로 있습니다. 서비스를 멈추려면 `own stop`(실행 중인 세션이 있으면 묻습니다).
- launcher가 처음 만드는 `%USERPROFILE%\.config\own-open-code\opencode.jsonc`의 `plugins`는 `own-accounts`, `own-remote`, `own-telemetry` 순서입니다(`own config print`로 확인). SSH 호스트와 휴대폰 접근은 `own-remote`가 있어야 됩니다.
  - 이전 launcher(0.1.0)가 만든 파일에는 `own-remote`가 없습니다. `own-accounts` 바로 다음 줄에 `"C:/Users/<사용자>/AppData/Local/own-open-code/app/<설치된 버전>/plugins/own-remote",`를 넣고 `own restart`를 실행합니다(버전은 `own status`의 `installed`. 이후 업데이트·되돌리기 때 launcher가 이 항목도 함께 고칩니다). `own config init --force`로 다시 만들어도 됩니다(앱에 든 Claude 구독 플러그인 항목도 함께 들어갑니다. 이전 파일은 `opencode.jsonc.bak-<시각>`으로 남습니다).

**launcher 명령**

| 명령 | 하는 일 |
|---|---|
| `own start` / `own stop` / `own restart` | 서비스 시작·중지·재시작. 실행 중인 세션이 있으면 묻습니다(`--force`로 건너뜀) |

## 4. 계정 추가

`계정`(사이드바) → `계정 추가`. 계정 = 로그인 1개 또는 API 키 1개입니다. 계정을 더하거나 바꿔도 실행 중인 세션은 바뀌지 않습니다. 계정 추가·키 교체·가져오기는 PC의 창에서만 됩니다.

### 4.1 API 키

| 유형 | 추가 입력 |
|---|---|
| OpenAI API 키 | `조직 ID`, `프로젝트 ID`(선택) |
| Anthropic API 키 | `워크스페이스 이름`(선택, 표시용). Claude를 쓰는 공식 방법입니다 |
| DeepSeek, xAI, OpenRouter | 없음 |
| 기타 OpenAI 호환 | `Base URL`, 모델 id, 모델마다 `컨텍스트 한도(토큰)`, 요율(선택, 없으면 토큰만 표시) |

1. 유형 카드 → `이름`, `API 키`(붙여넣기 가능).
2. `연결 테스트 후 추가`. 실패하면 `키가 거부되었습니다 ({상태}).`
3. 같은 조직의 키이면 알려 줍니다. 별도 계정으로 추가되지만 한도 여유는 늘지 않습니다.

- 키는 `%LOCALAPPDATA%\own-open-code\vault\`에 Windows DPAPI(현재 사용자)로 암호화해 저장합니다. OpenCode DB에는 저장하지 않습니다. 화면에는 끝 4자리만 다시 보입니다.
- 계정 `⋯`: 이름·색 바꾸기, `키 교체`, `연결 테스트`, `예산 설정…`, `잔액·키 조회 끄기`, `이 프로바이더의 기본 계정으로`, `끄기만 하기`, `제거`(키를 지우며 복구할 수 없음).

### 4.2 ChatGPT 구독 로그인

`ChatGPT 구독`(Plus · Pro · Business).

- `코드로 로그인`(기본): 화면의 코드를 https://auth.openai.com/codex/device 에 입력합니다. 이 PC나 다른 기기의 브라우저 어디서든 됩니다.
- `브라우저로 로그인`: 이 PC의 브라우저로 로그인합니다. Codex CLI 로그인과 포트 1455가 겹칠 수 있습니다.
- 이미 있는 계정으로 다시 로그인하면 `기존 계정 로그인 갱신`을 제안합니다. 다른 ChatGPT 계정으로 로그인되면 거절합니다.
- 토큰은 vault에 저장하고 이 앱이 갱신합니다.

### 4.3 이전 앱(codex-multi-provider)에서 가져오기

이전 앱의 ChatGPT 로그인 프로필을 찾으면 `이전 앱에서 가져오기` 카드가 보입니다. 행을 고르고 방식을 정한 뒤 `다음 →` → 확인 → `연결하기`/`인수하기`.

| | 연결 (권장) | 인수 |
|---|---|---|
| 토큰 | 이전 앱의 로그인 파일을 **읽기만** 합니다 | vault로 한 번 복사하고, 그 뒤 이전 파일은 읽지 않습니다 |
| 누가 갱신하나 | **이전 앱만** | **이 앱만** |
| 이전 앱에 미치는 영향 | 없음. 이전 앱을 계속 쓰면 됩니다 | 이 앱이 처음 갱신하면 이전 앱의 그 프로필은 **다시 로그인해야 할 수 있습니다** |
| 이전 앱을 오래 안 켜면 | 토큰이 만료되어 이 계정이 멈춥니다(`이전 앱 갱신 대기`). 이전 앱에서 그 프로필을 열면 1분 안에 다시 동작합니다 | 상관없음 |
| 이 앱에서 제거하면 | 이전 앱의 로그인 파일은 건드리지 않습니다 | vault 파일을 지웁니다 |

- 이전 앱을 계속 쓰는 동안은 연결, 그만 쓰거나 자주 켜지 않으면 인수를 고릅니다.
- 연결 계정의 `⋯` → `이 앱으로 인수…`로 나중에 바꿀 수 있습니다. 연결 계정에서 `다시 로그인`하면 인수와 같아집니다.
- 이전 앱에서 그 프로필이 다른 ChatGPT 계정으로 바뀌면 쓰지 않고 멈춥니다(`이미 가져온 계정과 다른 ChatGPT 계정입니다`).
- 연결 계정은 SSH 호스트에서 막힐 수 있습니다(이전 앱이 아직 갱신하지 않은 경우, 10.4).

#### 이전 앱에 저장된 API 키 연결 (DeepSeek 등)

가져오기 대화상자의 `API 키`에 이전 앱이 저장한 키(예: DeepSeek, `https://api.deepseek.com · deepseek-flash`)가 보입니다. `연결…` → 이름 확인 → `연결하기`. 연결할 때 키 확인용으로 요청을 한 번 보냅니다.

- **연결만 할 수 있습니다.** 키는 이 앱에 복사하지 않고, 요청할 때 이전 앱의 암호화된 키 파일을 읽기만 합니다(Windows DPAPI, 메모리 안에서만 복호화).
- 이전 앱에서 키를 바꾸면 여기서도 바뀝니다. 이전 앱에서 키를 지우면 이 계정은 멈춥니다(`설정 오류`).
- 이 계정은 `키 교체`가 없습니다. 키는 이전 앱에서 바꿉니다.
- 이 앱에서 제거해도 이전 앱의 키 파일은 건드리지 않습니다.

### 4.4 Claude 구독 (서드파티 플러그인, 약관 위험)

Claude Pro/Max 구독은 서드파티 플러그인 `opencode-claude-auth-v2`(heymaaz, MIT, 고정 버전 `0.4.0-beta.5`)의 슬롯으로만 씁니다. 플러그인 자체는 own-open-code가 만든 코드가 아닙니다. **공식적인 방법은 Anthropic API 키입니다(4.1).**

- **앱에 포함, 늘 켜짐.** 앱을 빌드할 때 커밋된 lock의 고정 버전을 받아 무결성을 확인하고, own의 패치(Claude 계정 여러 개, 대화마다 정한 계정 하나만 사용, 다른 계정의 토큰을 빌리지 않음)를 적용해 `%LOCALAPPDATA%\own-open-code\app\<버전>\plugins\claude-auth`에 둡니다. 사용자 PC에서는 실행 중에 아무것도 내려받거나 설치하거나 패치하지 않습니다. 플러그인은 앱 업데이트로만 바뀌고, 뺄 수 없습니다. Claude 계정을 연결하기 전에는 아무 요청도 보내지 않습니다.
- **위험(동의는 받지 않고 안내만 합니다).** `계정 추가 → Claude 구독`에서 가져오기 전에, 그리고 Claude 카드의 `위험 안내 보기`에서 10가지 위험 안내를 보입니다.
  - Anthropic 약관은 서드파티 앱이 Claude 구독 로그인(OAuth)을 쓰는 것을 허용하지 않습니다. 계정이 제한되거나 정지될 수 있습니다.
  - 플러그인은 요청을 Claude Code가 보낸 것처럼 표시합니다.
  - 구독 한도가 아니라 추가 사용량(API 요금)으로 청구될 수 있습니다. 그래서 이 슬롯의 비용은 `비용 알 수 없음`으로 표시합니다.
  - 구독 로그인 토큰은 OpenCode DB에 평문으로 저장됩니다(플러그인의 설계).
  - Claude Code와 토큰을 함께 씁니다. 동시에 쓰면 다시 로그인해야 할 수 있어, 새로 추가하는 계정은 이 앱 전용 로그인 폴더를 씁니다.
  - 한 PC에서 Claude 구독 계정 여러 개를 함께 쓰고 한도가 차면 다른 계정으로 바꾸는 것은 Anthropic이 알아챌 수 있고, 여러 계정이 함께 제한·정지될 수 있습니다.
- **순서**
  1. Claude Code에서 먼저 로그인합니다(`claude auth login`).
  2. `계정 추가 → Claude 구독`(또는 Claude 카드의 `연결 없음` 옆 `연결…`) → 위험 안내 확인 → `Claude Code 구독 가져오기` → `다음`. 끝나면 `Claude 구독 슬롯을 연결했어요. 이 슬롯에는 어디서나 비공식 배지가 붙어요.`가 보입니다.
- 이 슬롯에는 어디서나 `비공식` 배지가 붙습니다. 다른 회사 계정과는 자동 전환하지 않고(이 PC의 Claude 계정끼리는 `Claude 계정 사이`, 새로 설치하면 `끄기`), 자동 압축은 v2 기본(고정)입니다. SSH 호스트에서는 Claude 카드의 `SSH 원격 호스트에서 쓰기`에서 켠 호스트에서만 이 PC를 거쳐 씁니다(10.4). 호스트를 처음 켤 때 원격 사용 고지에 동의합니다(`위 내용을 이해했으며, 본인 책임으로 사용합니다.` → `동의하고 켜기`, 이 PC에 기록).
- **계정 더하기**: `계정` 화면의 Claude 묶음 아래 `Claude 계정 추가` → `로그인 시작`. 이 PC에 Claude Code 로그인 창이 열리고, 브라우저에서 로그인만 마칩니다(앱은 비밀번호나 토큰을 보지 않습니다). 이 PC의 Claude Code에 이미 로그인해 둔 계정은 `이 PC의 기존 Claude Code 로그인 가져오기`로 가져옵니다. 패치나 재시작은 필요 없습니다. 로그인 추가는 이 PC의 창에서만 됩니다. 대화마다 전환기(`Ctrl+.`)에서 `Claude · {이름}`을 고릅니다.
- **다시 로그인**: 로그인이 없거나 만료된 계정 카드는 `이 계정의 로그인이 없거나 만료됐어요 — [다시 로그인]을 누르세요.`를 보입니다. `다시 로그인`(카드 `⋯`에도 있음)은 그 계정의 로그인 폴더로 같은 Claude Code 로그인 창을 엽니다(`다시 로그인했어요: {이름}`). 대화가 그 계정의 로그인을 읽지 못하거나 갱신하지 못하면, 오류가 계정 이름과 함께 `[다시 로그인]`을 안내하고 요청을 보내지 않습니다. 다른 계정의 로그인으로 대신 보내지 않습니다.
- **카드 메뉴**: 슬롯 카드 `⋯`는 `이름 바꾸기` · `색 바꾸기` · `구독 다시 가져오기` · `다시 로그인`, 추가한 계정 카드 `⋯`는 `이름 바꾸기` · `색 바꾸기` · `새 대화의 기본으로` · `다시 로그인` · `계정 빼기…`입니다.
- 처음 연결한 계정(슬롯)이 읽는 Claude Code 로그인 폴더는 기본 `%USERPROFILE%\.claude`입니다. 다른 폴더를 쓰려면 PowerShell에서 `own restart --claude-config-dir "<폴더>"`(`default`면 기본값 `%USERPROFILE%\.claude`)를 실행합니다(`OWN_HOME\claude-auth.json`에 기록).
- **쓰지 않으려면**: 플러그인은 뺄 수 없습니다. Claude 계정을 연결하지 않거나, 추가한 계정을 `계정 빼기…`로 뺍니다(`로그인 폴더도 지우기`를 체크하면 이 앱이 만든 로그인 폴더도 지웁니다). 로그인이 없으면 슬롯은 아무것도 보내지 않습니다.
- `설정 > 플러그인`의 `서드파티 · Claude 구독`에 상태가 보입니다: 패키지 `opencode-claude-auth-v2`, 상태 `앱에 포함 · {버전} · 동작 중`(또는 `… · 불러와지지 않음`, `이 빌드에 없음`), 무결성 `앱의 기록과 일치`, 순서 `정상`.
- 카드에 `앱에 든 Claude 구독 플러그인이 아직 쓰이지 않고 있어요. 서비스를 다시 시작하면 불러와져요.`가 보이면 `지금 다시 시작`(데스크톱) 또는 `own restart`. `앱에 든 Claude 구독 플러그인 파일이 바뀌었어요(무결성 불일치). 앱을 다시 설치하세요.`나 `이 앱 설치에 Claude 구독 플러그인이 없어요. 앱을 다시 설치하세요.`면 설치 파일을 다시 실행합니다.
- 플러그인을 직접 설치해 쓰던 이전 버전에서 업데이트하는 경우는 2.3을 봅니다.

## 5. 모델 @ 계정 전환

### 5.1 캐시가 왜 중요한가

- 프로바이더는 같은 계정·모델로 보낸 요청의 앞부분(대화 문맥)을 캐시합니다. 캐시에서 읽은 입력은 정가의 일부로 청구되고 구독 한도도 덜 씁니다.
- **캐시는 계정·모델마다 따로입니다.** 다른 계정이나 모델로 바꾸면 다음 요청이 문맥 전체를 캐시 없이 다시 읽습니다. 이것이 `캐시 재작성`이고, 긴 세션일수록 비쌉니다.
- 캐시는 시간이 지나면 식습니다. 상태 표시: `따뜻함 · 약 N분` / `식는 중` / `차가움` / `알 수 없음`. 유지 시간은 프로바이더마다 다르고(예: Anthropic 약 5분, DeepSeek 수 시간~수일) 모두 추정입니다.
- 압축(7장)이 끝나면 모든 계정의 캐시가 차가워집니다. 그래서 "압축 직후"는 전환 비용이 거의 없는 시점입니다.
- 이미 식은 세션(오래 쉰 세션)은 머물러도 다시 읽으므로 전환 비용이 거의 없습니다.

### 5.2 전환기

- 입력창의 `{모델} @ {계정}` 칩, 또는 `Ctrl+.`(`Ctrl+'`).
- 목록: `현재 사용 중`, `최근`, `추천`, 계정별 모델, `추론 강도`. 행마다 `전환 비용 ≈ 캐시 재작성 {토큰} · {금액}` 또는 `전환 비용 없음`.
- 추론 강도만 바꾸면 모델에 따라 캐시가 유지되기도 하고(`전환 비용 없음 (추론 강도만 변경)`) 깨지기도 합니다.
- 쓸 수 없는 계정은 흐리게 이유와 함께 보입니다(`인증 만료 — 다시 로그인`, `한도 도달 · … 리셋`, `이전 앱 갱신 대기` 등).
- 언제 묻는지(기본값, `설정 > 전환 정책`에서 바꿈)
  - 아직 턴이 없는 새 세션: 곧바로 적용합니다.
  - 재작성 20k 토큰 미만: 곧바로 적용하고 알림에 `되돌리기`를 둡니다. 되돌리기는 새 계정으로 첫 요청을 보내기 전까지만 됩니다.
  - 20k–100k: `적용 · +$0.21`처럼 버튼에 비용을 붙여 한 번 더 누르게 합니다.
  - 100k 이상, 보정된 한도의 5% 이상, 또는 $0.50 이상: 전환 비용 대화상자(5.3).
- 턴이 도는 중이면 `현재 턴이 끝나면 적용`입니다. 턴 도중에 계정을 바꾸지 않습니다.

### 5.3 전환 비용 대화상자

`계정 전환: {이전} → {대상}`. 선택지(쓸 수 없는 것은 이유와 함께 흐리게):

| 선택지 | 뜻 | 언제 |
|---|---|---|
| `지금 전환` | 곧바로(바쁘면 턴 끝에) 전환. 문맥 전체를 대상에서 다시 읽음 | 짧은 세션, 급할 때 |
| `압축 후 전환` | 지금 계정(캐시가 따뜻함)에서 요약한 뒤 전환. 재작성량이 줄고 이후 요청도 작아짐. 최근 15k 토큰은 원문 유지 | 긴 세션. 대상 창이 작아 그대로는 넘칠 때는 이것만 가능 |
| `전환 후 압축` | 현재 계정을 쓸 수 없을 때 대신 보임. 대상에서 요약 | 현재 계정이 한도·인증 문제일 때 |
| `캐시가 식은 뒤 전환` | 지금은 현재 계정으로 계속하고, 다음 압축 직후 또는 약 N분 쉬면 자동 전환. 추가 비용 거의 없음(추정). 기한 안에 없으면 다시 묻기 | 급하지 않을 때. 캐시 유지 시간을 모르면 `불확실` 태그 |
| `새 세션으로 인계` | 요약을 첫 메시지로 넣은 새 세션. 원래 세션은 남음. 문맥 일부 손실 | 문맥이 너무 길 때 |
| `곁가지 포크`(`더 보기`) | 복제한 세션만 전환. 원 세션은 현재 계정 캐시 유지 | 잠깐 다른 모델에 물어볼 때 |

- 비용은 "머물 때보다 더 드는 양"입니다. 과금 단위가 다르면(credits와 $) 더하지 않고 나란히 적습니다.
- 라우터가 확실히 싸다고 판단한 선택지에만 `권장`이 붙습니다.
- 프로바이더가 바뀌면 이전 턴의 추론 기록 일부는 새 모델에 전달되지 않습니다. 돌아올 때 원래 계정의 캐시가 살아 있으면 다시 씁니다.
- `이 세션에서는 {토큰} 미만이면 다시 묻지 않기`로 세션별로 확인을 줄일 수 있습니다.
- 예약한 전환은 입력창 위 칩(`예약됨: …· 취소`)으로 보입니다. 예약 중에 보낸 메시지는 현재 계정으로 실행됩니다.

### 5.4 한도에 닿았을 때, 자동 전환

- 배너 `{계정}의 {창} 한도에 도달했습니다 · {시각} 리셋` → `다른 계정으로 전환…` / `리셋까지 대기` / `턴 중단`.
- `리셋까지 대기`는 리셋 시각에 `계속` 메시지를 보내 턴을 이어 갑니다. 이 메시지는 대화에 남습니다(`문구 바꾸기` 가능).
- 짧은 429는 계정을 바꾸지 않고 재시도합니다(`요청 한도 — N초 후 재시도`).
- **자동 전환은 API 키 계정끼리만** 됩니다(계정의 `자동 전환 허용`). 구독 계정(ChatGPT, Claude)은 한도 우회로 볼 수 있어 자동으로 돌리지 않습니다.
- 전환이 잦으면 `자동 전환을 30분 동안 멈췄습니다`로 스스로 멈춥니다.

### 5.5 프리셋: 하위 에이전트를 어떻게 쓸지 (T1)

- **메인은 입력창에서, 프리셋은 일하는 방식입니다.** 입력창 아래 줄은 `[계정 ▾][모델 ▾][추론 강도 ▾][프리셋: … ▾] 울트라 ○`입니다. 계정·모델·추론 강도는 지금처럼 메인(그 대화의 LLM)만 바꾸고, 프리셋은 그대로입니다. 더 좋은 모델이 나오면 모델 단추에서 고르기만 하면 됩니다.
- **프리셋이 정하는 것은 셋입니다.**
  1. 하위 에이전트를 어디서 돌릴지: 처음 값은 `메인과 같게`입니다. `메인 계정의 더 가벼운 모델`(같은 계정, 같은 한도), 다른 회사 구독(예: ChatGPT 메인에 Claude 구독), 로컬 LLM, 사용자가 켠 API 키에 고정할 수 있습니다. `일마다 정하기`를 고르면 탐색·일반·리뷰(그리고 빠른 일·어려운 일)마다 따로 정하고 LLM이 일에 맞는 역할을 고릅니다.
  2. 얼마나 맡길지: `모델 기본`(처음 값. GPT는 요청할 때만, 그 밖은 모델이 판단) / `요청할 때만` / `도움될 때` / `적극적으로`. 추론 강도와 따로입니다.
  3. 안전 상한: 동시 3개, 메시지 하나당 최대 6개(`적극적으로`는 12개). 대화당은 처음에 제한 없음이고 `자세히`의 `대화당 상한 두기`로 켤 때만 막습니다. 넘는 요청은 기다리지 않고 막고 LLM이 다른 일을 하게 합니다.
- **프리셋은 프로바이더 묶음마다 있습니다.** ChatGPT 계정이 여럿이어도 ChatGPT 프리셋을 함께 씁니다. 묶음마다 잠긴 `평소대로`(그 회사 앱을 그냥 쓰는 것과 같음)와 `★`(그 묶음에서 먼저 쓰는 프리셋)가 있습니다.
- **고르기**: 프리셋 단추 → 프리셋 고르기. `비용 없음 · 바로 적용`이고 대화도 바뀌지 않습니다. 다른 묶음의 계정으로 바꾸면 그 묶음에서 이름이 같은 프리셋, 없으면 ★로 갑니다(전환 창에 `프리셋: … → …` 한 줄).
- **만들고 고치기**: `설정 > 프리셋`(묶음별 탭) 또는 프리셋 단추의 `새 프리셋…`·`편집…`. 시작 틀 셋(`가볍게 나눠 쓰기`, `다른 회사 리뷰`, `로컬로 탐색`)이 행을 채워 줍니다. 탭 맨 위 줄 `새 대화 기본 모델`이 그 묶음의 새 대화 처음 모델입니다(계정 카드에는 없습니다).
- **모델 묶음에서 알아서**(T4): ①에서 이것을 고르면 쓸 모델에 체크만 하면 됩니다(메인 계정에서 도는 모델, 다른 회사 구독은 회사마다 계정 하나, 로컬 LLM, 예산을 정한 API 키). LLM이 짧은 모델 카드를 보고 일마다 이름으로 고르고, 이름을 적지 않으면 탐색·빠른 일은 더 가벼운 모델, 리뷰는 다른 회사의 가장 강한 모델, 어려운 일은 더 강한 모델, 일반은 메인과 같게 돕니다. 돈이 드는 모델은 이 규칙이 고르지 않고, 그 계정의 월 예산을 넘으면 저절로 빠집니다. `추천 묶음`이 한 번에 채워 줍니다. 새 모델이 나와도 묶음은 그대로이고, 카드는 `자세히`의 `카드 새로 고치기`로만 바뀝니다.
- **돈이 드는 대상은 직접 켤 때만**: API 키 대상은 대상 고르기 맨 아래 `API 키로 돌리기 · 돈이 듭니다`에서만 고르고, 계정의 월 예산 안에서만 씁니다. 구독 대상이 한도에 걸려 다음이 API 키면 대화에 `… 한도 대기 · 리뷰를 DeepSeek(종량제)로 돌릴까요? [이 대화에서만] [아니오]`가 뜹니다.
- **같은 회사의 다른 구독 계정은 쓰지 않습니다.** ChatGPT 01이 메인이면 ChatGPT 02는 하위 에이전트로 고를 수 없고 목록에도 없습니다(같은 회사 모델은 `메인 계정의 …`으로). 메인을 01에서 02로 바꿀 때 01에서 하위 에이전트가 돌고 있으면 `[끝나면 바꾸기] [멈추고 바꾸기]`를 묻습니다.
- **막힌 하위 에이전트 요청**은 오류가 아니라 작은 칩입니다: `하위 에이전트 대기: 3개 실행 중`, `… 이번 메시지만 늘리기`, `하위 에이전트 요청을 막았습니다: …(은)는 이 프리셋에 없습니다 [하위 에이전트에 추가…] [그대로]`. 읽기 전용 역할(탐색·리뷰)은 파일을 고치거나 컴퓨터를 쓰지 않습니다.
- 문맥 창은 언제나 모델의 전체 창입니다. 프리셋은 압축이나 대화 크기를 바꾸지 않습니다.
- **원격 서버(SSH 호스트)의 대화**(T3): 이 PC의 프리셋이 그 호스트로 함께 옮겨지므로(프리셋을 바꾸면 따라감) 원격 대화의 프리셋 단추에도 같은 프리셋이 보이고 고르면 그 대화에 바로 적용됩니다. 만들고 고치는 곳은 언제나 이 PC입니다(`새 프리셋…`·`편집…`이 이 PC의 편집기를 엶). 수리 알림의 점은 이 PC의 대화에만 붙습니다. 아직 프리셋을 받지 못한 호스트(옛 버전, 처음 연결 직후)는 `평소대로`만 보이고 `이 원격 서버에는 아직 프리셋이 없어 평소대로만 씁니다`가 붙습니다. API 키(종량제) 대상은 이 PC가 알려 준 예산 상태로만 판단하고, 알 수 없으면 쓰지 않습니다.

### 5.6 울트라 (T1)

- 입력창의 `울트라` 스위치를 켜면 메인 추론 강도를 올리고(ChatGPT는 Codex 울트라와 같은 값, Claude는 그대로이고 `켤 때 강도도 xhigh로`를 고를 수 있음), 맡기는 정도를 `적극적으로`로, 상한을 울트라 상한으로 바꿉니다. 하위 에이전트는 메인과 같은 강도로 돕니다.
- 울트라 상한은 `설정 > 프리셋` 맨 위 `울트라 상한`에서 고릅니다: `아껴서`(동시 3 · 메시지당 12), **`추천`**(처음 값, 8 · 24), `크게`(64 · 128, 한도가 몇십 분 만에 바닥날 수 있음), `직접 정하기`. 어느 단계도 대화당 상한은 없습니다.
- 켜 있는 동안 입력창에 `울트라 · ChatGPT 01 5시간 42% · Claude 구독 18%`처럼 사용률이 늘 보입니다. 강도가 바뀌는 모델이면 켜고 끌 때 전환 비용 창이 한 번 뜹니다. 새 대화에서는 언제나 꺼져 있습니다.
- 울트라를 켠 채 계정이나 모델을 바꿨는데 새 모델의 울트라 강도로 바로 바꾸면 캐시를 다시 써야 하는 경우, 입력창에 `울트라 강도 맞추기`가 뜹니다. 누르면 같은 비용 창을 거쳐 바꿉니다.

### 5.7 프리셋 자세히와 수리 알림 (T2)

- **`자세히 ▸`**(프리셋 편집기 아래): 역할별 추론 강도(`중간 → 높음으로 보냄`처럼 지금 메인에서 실제로 보낼 단계가 보입니다), 역할마다 대상 순서(1순위가 안 되면 다음, 끝이면 `메인과 같게`), 나눠 맡기기 `안 함`, 안전 상한 셋, 이 프리셋의 울트라 상한, 이 프리셋이 넣는 안내문 미리 보기(읽기 전용), 그 묶음의 **가벼운 짝** 표(`GPT-6 Astra → GPT-6 Luna · 자동 [짝 바꾸기]`), `★ 이 묶음에서 먼저 쓰기`, `다른 묶음에 복사…`, 수리 기록. 메인 모델과 추론 강도는 여기에도 없습니다(입력창에서 고릅니다).
- **새 모델**: 계정에 새 모델이 생기면 모델 목록과 대상 고르기에서 14일 동안 `새` 표시가 붙습니다. 알림은 없고, 프리셋·짝·새 대화 기본 모델·지금 대화는 아무것도 바뀌지 않습니다. 쓰려면 직접 고릅니다.
- **은퇴 예정**(Codex): 그 모델이 쓰이는 자리에 흐리게 `10-14 은퇴 예정(Codex)`만 보입니다. 미리 바꾸라고 권하지 않습니다.
- **수리 알림**: 프리셋에 고정한 모델(또는 가벼운 짝, 새 대화 기본 모델)이 카탈로그에서 사라지면, 그 역할은 다음 대상이나 `메인과 같게`로 돌고 알림이 **모델마다 한 번** 뜹니다. 예: `리뷰 모델 GPT-5.5가 없어져 리뷰를 메인 모델로 돌립니다 · 프리셋 2개 [GPT-5.6 Sol로 고치기] [직접 고르기]`. 알림을 놓쳐도 입력창 프리셋 단추의 **점**과 그 메뉴, `설정 > 프리셋`의 그 묶음 탭에 남습니다. `[고치기]`는 제안된 모델로 그 자리만 바꾸고 수리 기록에 남깁니다. `[직접 고르기]`는 편집기를 그 역할의 `자세히`로 엽니다. 저절로 고쳐지는 것은 없습니다.
- **새 대화 기본 모델이 사라지면** `설정 > 프리셋`의 그 묶음 탭에 `ChatGPT 새 대화 기본 모델 GPT-5.5가 없어졌습니다. 새 대화는 GPT-6 Astra로 시작합니다 [바꾸기]`가 보입니다. 직접 고른 값은 지우지 않으므로 그 모델이 돌아오면 다시 씁니다.
- **지금 대화의 모델이 사라지면** 입력창 위에 `이 대화의 모델 GPT-5.5가 없어졌습니다. GPT-5.6 Sol로 바꿀까요? [바꾸기]`(추론 강도가 사라진 경우는 `이 모델에서 '매우 높음'이 없어졌습니다. 최대로 바꿀까요?`)가 뜨고, 보내기를 누르면 보내지 않고 입력을 남긴 채 전환기를 엽니다. 바꾸는 것은 늘 사용자입니다(전환 비용 창은 5.3과 같음).
- **`템플릿 갱신 있음`**: 계정 카드에 이 꼬리표와 `[갱신]`이 보이면 그 종류 모델의 이름·추론 강도 단계 같은 고정 항목이 바뀐 것입니다. 갱신하면 새 대화와 압축 직후부터 적용되고 진행 중인 대화는 그대로입니다. 새 모델·사라진 모델·한도·가격은 갱신 없이 따라갑니다.

## 6. 한도 패널

- 작업 패널 `계정·한도` 탭(`Ctrl+Shift+U`)과 사이드바 `한도`(대시보드, 기간 24시간·7일·30일).
- 계정 유형별 막대: ChatGPT 구독 `5시간`·`주간`, Claude 구독 `5시간`·`7일`, API 키 `이번 달 지출 / 예산`, DeepSeek `잔액`, OpenRouter `키 한도`.
- 색: 70% 미만 중립, 70–90% 주의, 90% 이상 위험.

| 태그 | 뜻 |
|---|---|
| `실측 · 방금` / `실측 · N분 전` | 응답 헤더·이벤트에서 관측한 값. 2분 이내면 흐린 글자, 15분 이내면 흐린 태그 |
| `오래됨 · N분 전` | 마지막 관측이 15분 넘음. 막대가 흐립니다. 구독 한도는 쓰지 않는 동안 갱신되지 않으므로 쉬는 계정에서는 정상입니다 |
| `추정` | 리셋 시각이 지나 새 관측이 없거나 속도 예측. 막대가 빗금입니다(`리셋됨(추정)`) |
| `보정 중` | 전환 비용을 구독 한도 %로 바꿀 비율을 아직 모름. %를 쓰지 않고 credits만 보입니다 |
| `로컬 집계` | 이 PC의 사용량 기록으로 계산. 다른 기기나 앱에서 쓴 양은 포함되지 않습니다 |
| `— 알 수 없음` | 값이 없음 |

- 비용과 credits는 모두 로컬 기록에 근거한 추정입니다.
- 잔액·키 조회는 공식 endpoint만, 계정당 최소 15분 간격입니다. 계정 `⋯` → `잔액·키 조회 끄기`로 끌 수 있습니다. 구독 계정은 조회하지 않습니다.

## 7. 자동 압축

문맥이 기준을 넘으면 코어가 대화 앞부분을 요약합니다. 기준은 `설정 > 자동 압축`에서 프로바이더 종류·계정·모델별로 정합니다.

| 종류 | 기본값 | 예 |
|---|---|---|
| ChatGPT 구독, OpenAI API, Anthropic API | `v2 기본`: 창의 85%(15%를 남김) | 872k 창 → 741.2k |
| Claude 구독 | `v2 기본 (고정)` | – |
| DeepSeek, xAI, OpenRouter | `종류 기본(보수적)`: 창의 60%, 최대 256k, 여유 32k 이상 | 1M 창 → 256k |
| 기타 OpenAI 호환 | `종류 기본(보수적)`: 창의 50%, 최대 128k, 여유 32k 이상 | 128k 창 → 64k |

- 보수적인 이유: 토크나이저가 달라 토큰 추정 오차가 크고, 한도 초과 뒤 자동 복구가 서버 문구에 따라 안 될 수 있으며, 호환 서버는 입력한 창 크기 자체가 틀릴 수 있기 때문입니다. 대신 압축이 잦아 요약 비용과 캐시 재작성이 늘 수 있습니다. 화면의 비용 비교 줄로 확인합니다.
- 우선순위(뒤가 이김): v2 기본 → 종류 → 종류·모델 → 계정 → 계정·모델 → 이 세션. 결과 옆에 출처가 붙습니다.
- `사용자 지정`: 비율(10–90%), 상한 토큰, 최소 여유. 90%보다 늦게 둘 수 없습니다.
- 저장할 때 곧바로 압축될 세션이 있으면 목록을 보이고 `그대로 적용` / `먼저 지금 기준으로 압축한 뒤 적용` / `취소`를 묻습니다. `다음 단계부터 적용됩니다`.
- **이 세션만**: 문맥 계기(`문맥 118k / 272k · 자동 압축 245k (v2 기본)`) → `이 세션 압축 설정…` → 더 일찍 압축하는 값만 넣을 수 있습니다. 서비스가 직접 적용하므로 앱 창을 모두 닫아도 적용됩니다.
- `지금 압축`: 문맥 계기, 헤더 `⋯`, `/compact`.
- 코어 설정 `자동 압축 켜짐`과 `최근 원문 유지 15,000 토큰`은 읽기 전용입니다. `opencode.jsonc`에 `compaction.buffer`를 넣으면 기준이 어긋나 경고 띠가 뜹니다.

## 8. 승인과 승인 모드

- **승인 모드**(헤더 알약, `Ctrl+Shift+A`는 메뉴를 열기만 함)

  | 모드 | 동작 |
  |---|---|
  | `읽기 전용` | 파일 수정과 셸 명령을 거절합니다. 도구 목록은 그대로라 캐시가 유지됩니다 |
  | `묻기` (기본) | 파일 수정과 셸 명령마다 묻습니다 |
  | `전체 허용` | 묻지 않고 파일을 고치고 명령을 실행합니다. OS 샌드박스는 없습니다. 한 번 확인을 받습니다 |

  - 실행 중인 하위 에이전트에도 적용됩니다. 새 세션의 기본값은 `설정 > 승인·권한`.
  - 어느 모드에서도 vault, 세션 DB, `service-own.json`, `.claude\.credentials.json`, `.codex\auth.json`, 이전 앱 프로필은 에이전트의 파일 도구로 읽거나 고칠 수 없습니다. 셸 명령까지 막지는 못하는 보조 장치이므로 `전체 허용`은 믿는 작업에만 씁니다.
- **승인 dock**(입력창 위): `한 번 허용`(`Enter`) / `항상 허용`(`Ctrl+Enter`) / `거절…`(`Esc`, 사유는 에이전트에 전달). dock에 포커스를 주려면 `Ctrl+Shift+Enter`.
  - `항상 허용` 아래에 저장될 범위가 보입니다(`이 프로젝트에서 "bun test*" 명령은 다시 묻지 않습니다`). 저장된 규칙은 `설정 > 승인·권한`에서 `취소`합니다.
  - 하위 에이전트의 요청도 부모 세션 dock에 `열기 →`와 함께 뜹니다.
- **웹 검색** 첫 사용 때 검색 서비스를 고르는 dock이 뜹니다. 권한이 아니라 서버 전역 설정이라 `전체 허용`이어도 한 번 묻고, 고르면 모든 세션·모델에 적용됩니다. `설정 > 웹 검색`(모델·계정 묶음, 2026-10-19 전에는 승인·권한 안)에서 지금 쓰는 서비스와 그 비용, 검색어가 가는 곳을 보고 미리 고르거나 바꿉니다. 대화의 검색 카드 제목이 답한 서비스를 말하고(`ChatGPT로 검색`, `Parallel로 검색 (무료)`), 그 아래 `검색 서비스 바꾸기`가 그 페이지로 갑니다. `웹 검색 끄기`는 모든 세션에 적용됩니다. ChatGPT 계정이 있으면 고르지 않아도 `ChatGPT` 검색이 기본이라 묻지 않습니다(어느 모델이든 ChatGPT 구독 사용량으로 검색).
- **프로젝트 플러그인**: 승인하지 않은 `.opencode` 플러그인이 있는 프로젝트에서는 계정 인증을 보내지 않습니다(`이 프로젝트에 승인되지 않은 플러그인이 있어…`). `설정 > 플러그인`에서 승인하거나, 믿을 수 없는 저장소는 `own restart --untrusted`로 엽니다.

## 10. SSH 원격 호스트

에이전트, 셸·파일 도구, 터미널이 Linux 호스트에서 돌고, 계정과 한도는 이 PC의 것을 씁니다.

### 10.1 지원과 준비

- 호스트: Linux x64 또는 arm64(glibc). `sh`, `tar`, `mktemp`만 있으면 됩니다. root 권한은 필요 없습니다. 여유 공간은 번들 크기의 약 3배.
- PC: `ssh.exe`(2.1), 키는 `%USERPROFILE%\.ssh\config`에 두기를 권합니다. own은 키를 만들거나 복사하지 않고, `known_hosts`도 고치지 않습니다.
- 암호문구 있는 키를 매번 묻지 않게 하려면 ssh-agent를 직접 켜고 `ssh-add`로 키를 올립니다(관리자 PowerShell. own은 시스템 설정을 바꾸지 않습니다).
- 서비스 설정에 own-remote 플러그인이 있어야 합니다(3장 끝). 없으면 `이 서비스에는 원격 호스트 기능(own-remote)이 없습니다`.

### 10.2 호스트 추가

1. 사이드바 `+ 원격 호스트 추가` 또는 `설정 > 원격 호스트`.
2. `~/.ssh/config의 호스트`에서 고르거나 `직접 입력`(`user@host` 또는 `user@host:port`), `표시 이름`.
3. `연결 확인`. 필요하면 비밀번호·암호문구 대화상자가 뜹니다. 값은 보낸 뒤 바로 지웁니다.
4. **호스트 키 확인**: 처음 보는 호스트면 `처음 연결하는 호스트입니다`와 지문(`SHA256:…`)이 보입니다. 서버 관리자가 알려 준 값과 같을 때만 `신뢰하고 연결`을 누릅니다(기본 포커스는 취소).
   - 이 질문은 호스트 추가와 호스트 메뉴의 `호스트 키 확인…`에서만 뜹니다. 그 밖의 연결(배경 재연결, 업데이트)은 모르는 키에서 멈추고 기다립니다.
   - 키가 바뀌었다는 오류는 앱이 고치지 않습니다. 확인한 뒤 `known_hosts`를 직접 고칩니다.
5. 설치 카드 `이 호스트에 own을 설치할까요?`: 설치 위치, 크기·필요 공간·여유 공간, 쓰는 파일, `관리자(root) 권한이 필요 없습니다`, `이 호스트의 opencode 설치는 건드리지 않습니다` → `설치하고 연결`.
6. 진행(`업로드` → `검증` → `원격 서비스 시작` …) 뒤 `연결되었습니다`: 에이전트 셸에서 찾은 도구와 PATH. `.bashrc`에만 있는 PATH가 있으면 `대화형 셸 설정 쓰기`를 권합니다.
7. `폴더 열기` → 원격 절대 경로 → `이 폴더에서 새 세션`.

### 10.3 호스트에 설치되는 것

설치는 이 PC의 번들을 SSH로 올리기만 합니다. 호스트가 인터넷에서 받는 것은 없습니다. XDG 변수가 없을 때의 경로:

| 경로(호스트) | 내용 |
|---|---|
| `~/.local/share/own-open-code/app/<버전>/` | own 채널 `opencode`, 플러그인(own-accounts, own-remote, own-team(팀 모드, T3)), `libexec/start.sh`, `manifest.json`. `app/current`는 symlink, 직전 버전 하나만 남김 |
| `~/.local/share/own-open-code/` | 계정 레지스트리 미러(`accounts.json` 등, **비밀 없음**)와 프리셋 미러(`presets.json`, T3), `run/`, `tmp/`, `spool/`(사용량 관측 대기열), `ops/`, `backup/` |
| `~/.local/share/own-open-code/tools/git-lfs/` | (T3) 그 호스트에서 큰 파일(Git LFS)을 쓰는 저장소로 팀 모드를 켤 때만 올리는 정적 `git-lfs`(고정 버전, sha256 확인). `current`는 symlink. sudo도 `~/.gitconfig` 변경도 없음(16.13) |
| `~/.config/own-open-code/` | `opencode.jsonc`, `service-own.json` |
| `~/.config/opencode/service-own.json`, `~/.local/state/opencode/service-own.json` | 서비스 설정 사본, 등록 파일 |
| `~/.local/share/opencode/opencode-own.db` | 원격 세션 DB(원격 세션의 원본) |

- 원격 서비스도 호스트의 `127.0.0.1`에만 열리고, 이 PC와는 SSH 터널로만 이어집니다.
- 호스트의 upstream `opencode` 설치는 읽지도 쓰지도 않습니다.

### 10.4 계정 키는 호스트에 남지 않습니다 (브로커)

- API 키, 로그인 토큰, vault는 호스트 디스크에 가지 않습니다. 이 PC의 인증 브로커가 요청마다 필요한 인증 헤더를 **lease**로 빌려 주고, 호스트는 그 값을 메모리에만 lease 동안(기본 15분) 둡니다. refresh 토큰은 이 PC를 떠나지 않습니다.
- PC와 끊기고 lease가 끝나면 원격 턴은 모델을 부르지 않고 안전하게 멈춥니다(`로컬 인증 브로커에 연결할 수 없어 모델을 부를 수 없습니다(안전하게 멈춤)`).
- 호스트 설정: `계정 범위`(모든 계정 / 선택한 계정만), `lease 시간(분)`, `끊김 유예(초)`. lease가 길수록 끊겨도 오래 돌지만 키가 원격 메모리에 오래 머뭅니다. 믿는 호스트에만 계정을 허용하세요.
- 호스트의 `프로젝트 설정`은 세 상태입니다. `끔`은 저장소에서 아무것도 읽지 않습니다(`AGENTS.md`도). `지시 파일만 (AGENTS.md)`은 저장소의 `AGENTS.md`만 읽고 플러그인·MCP·에이전트·명령·스킬·프로젝트 `opencode.json`은 읽지 않습니다. 새로 추가하는 호스트의 기본값입니다. `켬`은 전부 읽으며, 그 호스트에서 여는 저장소의 플러그인이 원격 작업에 쓰이는 키를 읽을 수 있습니다. 이전 버전에서 추가한 호스트는 저장된 값(`끔`)이 그대로이므로 호스트 설정에서 바꿉니다.
- Claude 구독은 PC의 Claude 카드 `SSH 원격 호스트에서 쓰기`에서 켠 호스트에서만 씁니다. 요청은 이 PC를 거쳐 나가고 토큰은 호스트로 가지 않습니다. PC가 꺼져 있거나 연결이 끊기면 쓸 수 없고, 진행 중인 답은 끊깁니다.

### 10.4a 이 PC의 MCP 서버를 호스트에 설치

- 이 PC의 MCP 서버는 호스트 대화에 저절로 가지 않습니다. `설정` > `MCP 서버` > `SSH 호스트에서 쓰기`에서 호스트를 고르면 서버마다 `설치됨` / `설치 가능` / `준비 필요` / `AI 도움 필요` / `이 PC 전용` / `호스트 최신 아님`이 보입니다(호스트가 가진 node·npx, uv, python, docker를 읽기만 해서 판단, sudo 없음).
- `이 호스트에 설치`나 `모든 서버를 <호스트>에 설치…`는 호스트의 own 설정에 서버를 쓰고, npx·uvx 패키지를 사용자 공간에 미리 받고, 호스트에서 연결 시험을 합니다.
- 키 같은 값은 `이 키를 <호스트>에 보내기`를 누를 때만 갑니다. 호스트 디스크에는 남지 않고 그 서비스 메모리에만 있으며, 보내기 전에는 그 서버가 꺼져 있습니다. `보낸 값 거두기`로 거둡니다.
- 준비가 필요한 서버는 `AI에게 설치 맡기기`: 그 호스트에 새 대화가 열리고 AI가 사용자 공간에 설치한 뒤 서버를 등록하고 시험합니다. 명령은 승인 모드대로 묻습니다.
- PC에서 고친 서버는 호스트에서 `PC와 다름`으로 보이고 `업데이트`로 다시 맞춥니다. 자세히는 설명서 10.15, 22장.

### 10.5 연결, 끊김, 업데이트, 제거

- **끊김 ≠ 중지.** SSH가 끊기거나 앱·서비스를 닫아도 원격 서비스와 턴은 계속됩니다(lease가 남은 동안). 원격을 멈추려면 호스트 `⋯` → `현재 턴이 끝나면 중지`.
  - 예외: `이 호스트는 SSH가 끊기면 원격 작업도 멈춥니다` 경고가 보이면 호스트 관리자가 linger를 켜야 합니다.
- 사이드바 호스트 상태: 초록 점(연결됨, 글 없음), `연결 중…`, `인증 필요`, `연결 끊김`(목록 위에 `저장해 둔 목록 · N분 전`), `업데이트 필요`(`⤓`), `다른 PC가 관리 중`.
- **업데이트**: 이 PC의 버전을 바꾸면 모든 호스트가 `업데이트 필요`가 됩니다. `업데이트…` → `현재 턴이 끝나면 업데이트 (기본)`. 업데이트 전에 원격 DB를 백업하고, 실패하면 되돌립니다.
- 호스트 상태 패널(`설정 > 원격 호스트 > {호스트}`): 버전, 브로커, 활성 lease, 셸 환경, 경고, `진단` 복사, `이 PC로 가져오기`(다른 PC가 관리 중일 때).
- **제거**: `⋯` → `제거…`. 기본은 이 PC의 호스트 기록, 목록, 브로커 키만 지웁니다. `원격 설치도 지우기`를 고르면 원격 `app/`, `run/`, `tmp/`, `spool/`, `tools/`, 미러를 지웁니다. 원격 DB와 `backup/`은 남습니다. 그 호스트에 lease를 준 API 키 목록이 보이며, 호스트를 더 믿지 않으면 그 키를 교체합니다. 그 호스트에서 큰 파일 저장소로 팀 모드를 썼다면 `tools/`를 지운 뒤 그 저장소의 git 큰 파일 설정이 없는 도구를 가리키게 되니, 원격 설치를 지우기 전에 팀 모드를 끄고 그 저장소의 `filter.lfs.*` 설정(저장소 안 `git config --local`)을 정리하세요.

## 11. 휴대폰·원격 접근 (페어링 + Tailscale serve, 앱 연결)

휴대폰(또는 다른 기기)의 브라우저에서 PC의 세션(로컬과 SSH 호스트 모두)을 보고 이어서 조작합니다. `설정 > 기기`는 PC의 창(데스크톱 앱, 이 PC의 브라우저 폴백)에만 있습니다. `이 서비스에는 원격 접근(own-remote)이 없습니다`가 보이면 `opencode.jsonc`에 own-remote가 빠진 것입니다(3장).

### 11.1 구조

- 서비스 안의 **게이트웨이**가 `127.0.0.1`의 별도 포트에만 열립니다. LAN 주소나 `0.0.0.0`으로는 열 수 없습니다.
- 바깥에서는 **Tailscale serve**로만 닿습니다. tailnet(같은 Tailscale 계정에 로그인한 기기) 안에서만 `https://<PC 이름>.<tailnet>.ts.net`으로 보이고, 전송은 WireGuard + HTTPS입니다.
- 앱은 Tailscale을 설치하거나 설정하지 않습니다. 설치 여부만 보고 안내를 보입니다. 설치·로그인·`serve` 설정은 사용자가 합니다.
- **Tailscale Funnel(공개 인터넷), 포트 포워딩, LAN 공개는 쓰지 마세요.**

### 11.2 연결하기

1. PC와 휴대폰에 Tailscale을 설치하고 같은 tailnet(같은 Tailscale 계정)에 로그인합니다.
2. PC: `설정 > 기기` → `원격 접근 게이트웨이`의 `켜기` → `게이트웨이를 켤까요?`에서 `켜기`. 상태가 `켜짐 · http://127.0.0.1:28539`로 바뀝니다(기본 포트 28539, `포트` 칸에서 바꿈). 설정은 `%LOCALAPPDATA%\own-open-code\gateway.json`에 남습니다.
3. 같은 화면의 `Tailscale` 줄을 봅니다.
   - `이 PC에 Tailscale이 없습니다…`, `Tailscale이 꺼져 있습니다…`, `Tailscale에 로그인되어 있지 않습니다…`: 안내대로 Tailscale을 준비합니다. 앱은 확인만 합니다.
   - `Tailscale 연결됨 · <PC 이름>`: 아래 명령과 `복사` 버튼이 보입니다. PC의 PowerShell에서 **직접** 한 번 실행합니다(`--bg`라 창을 닫아도 유지됩니다):
     ```powershell
     tailscale serve --bg --https=443 http://127.0.0.1:28539
     ```
     그 뒤 `tailscale serve가 이 게이트웨이를 tailnet에 열고 있습니다: https://<PC 이름>.<tailnet>.ts.net`이 보입니다.
4. `새 기기 연결` → `기기 이름`, `권한`(11.3), `볼 수 있는 서버`(`모두` 또는 `고르기`), `만료`(`7일`·`30일`·`90일`) → `QR 만들기`. QR은 한 번만 쓸 수 있고 5분 뒤 만료됩니다(`다시 만들기`).
   - Tailscale이 없으면 `Tailscale이 없어 이 PC에서만 열리는 주소입니다`가 붙습니다. 그 QR은 휴대폰에서 열리지 않습니다.
5. 휴대폰 카메라로 QR을 엽니다(또는 `또는 이 링크를 휴대폰에서 여세요`의 링크). 휴대폰에 `PC에 연결` · `PC에서 승인을 기다립니다`와 `확인 번호`(숫자 4개)가 보입니다.
6. PC에 `기기 연결 요청` 대화상자가 뜹니다: `{기기}이(가) 연결을 요청합니다 · 확인 번호 {번호}`. **휴대폰의 번호와 같을 때만** `허용`합니다(2분 안에). 다르면 `거부`. QR 코드만으로는 기기가 등록되지 않습니다.
7. 휴대폰이 `연결을 마치는 중…` 뒤 세션 목록을 엽니다. PC의 `연결된 기기`에 그 기기가 보입니다.
8. (선택) 휴대폰 브라우저 메뉴의 `홈 화면에 추가`로 앱(PWA)처럼 씁니다. 오프라인이면 마지막 세션 목록을 보여 줍니다.
   - Android Chrome의 설치 앱은 Chrome과 로그인(쿠키)을 같이 씁니다.
   - iPhone은 홈 화면 앱이 Safari와 쿠키를 따로 가집니다. 홈 화면 앱에서 `이 기기는 PC에 연결되어 있지 않습니다`가 보이면 Safari에서 쓰세요(이 빌드에서 확인하지 못했습니다).

### 11.3 기기 권한

`새 기기 연결`과 기기의 `권한 바꾸기`에서 고릅니다.

| 권한 | 할 수 있는 것 | 기본 |
|---|---|---|
| `읽기` | 세션 목록·대화 보기, 계정·한도 보기, 알림 피드 | 켬 |
| `프롬프트` | 메시지 보내기, 중단, 대기열, 권한 요청에 `한 번 허용`·거절, 질문 답, 압축·포크 | 켬 |
| `전환` | 모델 @ 계정 전환, 예약, 세션 압축 설정 | 켬 |
| `파일` | 폴더·파일·diff 보기, 첨부 올리기 | 끔 |
| `터미널` | 작업 패널의 터미널. 입력창의 `!` 셸 모드는 휴대폰에서 늘 꺼져 있습니다 | 끔 |
| `관리` | 계정 점검, 정책·요금표 변경, SSH 호스트 연결·끊기 | 끔(`휴대폰을 잃어버리면 이 PC에서 명령을 실행하거나 설정을 바꿀 수 있습니다`) |

- 어떤 권한으로도 안 되는 것: 계정 추가·키 교체·가져오기(`Claude 계정 추가`·`다시 로그인` 포함), 프로젝트 플러그인 승인, `항상 허용`(휴대폰의 권한 dock에는 이 버튼이 없습니다), SSH 비밀번호·호스트 키 응답, 기기·게이트웨이 관리. PC의 창에서 합니다.
- SSH 호스트 세션은 게이트웨이가 `/srv/<호스트>/…`로 중계합니다. 휴대폰은 SSH 키, 원격 서비스 비밀번호, 원격 토큰을 받지 않고, 호스트에 직접 접속하지도 않습니다.
- 브라우저 패인은 휴대폰에 없습니다.

### 11.4 토큰, 폐기, 제한

- 기기 토큰은 기기마다 따로이고, PC에는 **해시만** 저장합니다(`%LOCALAPPDATA%\own-open-code\devices.json`). 휴대폰 브라우저는 HttpOnly 쿠키로만 가집니다.
- 수명: 고른 만료(기본 30일). 14일 동안 쓰지 않아도 만료됩니다. 만료·폐기되면 휴대폰에 `이 기기의 연결이 만료되었거나 폐기되었습니다. PC의 설정 > 기기에서 다시 연결하세요.`
- 휴대폰을 잃어버리면 PC의 `설정 > 기기` → `연결된 기기`에서 `폐기`(또는 `모두 폐기`). 열린 요청과 연결이 곧바로 끊깁니다(시험에서 0.3초). 다른 기기와 PC는 영향이 없습니다.
- 휴대폰이 오프라인이던 동안의 사건(이 PC 세션의 턴 완료·권한 요청 등, 호스트 끊김)은 알림 피드로 다시 받습니다. SSH 호스트 세션의 사건은 아직 피드에 없습니다. 끊긴 동안 쓴 초안은 자동으로 보내지 않습니다. 푸시 알림은 다음 단계(M2)입니다.
- PC가 잠들거나 꺼지면 붙을 수 없습니다.
- 게이트웨이를 켜 두면 `own start`·`own restart`(데스크톱 앱이 서비스를 띄울 때도 같은 launcher)가 서비스를 띄운 뒤 게이트웨이도 켭니다(`own: remote access gateway listening on …`). launcher 없이 띄운 서비스에서는 데스크톱 앱이나 브라우저 폴백을 한 번 열어야 게이트웨이가 켜집니다. 로그온 때 자동 시작(`own logon`)은 아직 없습니다.
- 게이트웨이를 끄려면 `설정 > 기기`의 `끄기`. 연결된 기기가 모두 끊기고 등록은 남습니다.

### 11.5 앱으로 연결: Android 앱, 다른 PC의 데스크톱 앱

브라우저 대신 Own OpenCode 앱으로 이 PC에 접속합니다. 앱은 **이 PC가 만든 인증서의 지문**만 믿습니다. 공용 인증 기관, DDNS 업체, Tailscale 서버는 믿지 않으므로 그쪽이 침해되어도 대화와 기기 토큰을 볼 수 없습니다. 설계는 [08-app-access.md](08-app-access.md)에 있습니다.

1. PC: `설정 > 기기`에서 게이트웨이를 켠 뒤, `앱 연결` → `앱 연결 켜기` → `켜기`. `켜짐 · 127.0.0.1:28540 (TLS)`와 `인증서 지문`이 보입니다. 이 포트도 이 PC 안에서만 열립니다.
2. 밖에서 닿는 경로를 하나 이상 준비합니다. 둘 다 준비하면 앱은 Tailscale 경로를 먼저 쓰고, 안 되면 3초 안에 DDNS 경로로 넘어갑니다.
   - **Tailscale 경로**: 휴대폰·노트북에도 Tailscale이 있어야 합니다. 화면의 명령을 PowerShell에서 한 번 실행합니다. Tailscale은 바이트만 전달하고 TLS를 풀지 않습니다.
     ```powershell
     tailscale serve --bg --tcp=28540 tcp://localhost:28540
     ```
   - **DDNS 경로**: Tailscale 없이 도메인으로 접속합니다(원격 데스크톱을 도메인으로 쓰는 것과 같은 방식).
     1. `도메인(DDNS) 또는 공인 IP`에 도메인(예: `myhome.iptime.org`)을, `외부 포트`에 `28541`(기본)을 넣고 `저장`.
     2. 화면에 나온 두 줄을 **관리자 PowerShell**에서 한 번 실행합니다(포트 전달 `netsh interface portproxy`와 방화벽 허용 규칙). 앱 자체는 127.0.0.1에만 열려 있고, 밖으로 여는 것은 이 규칙입니다. 그래서 `opencode.exe`에 대한 방화벽 창은 뜨지 않습니다. 방화벽 규칙은 `개인` 네트워크에만 걸리므로, 집 네트워크가 Windows에서 `공용`으로 되어 있으면 `개인`으로 바꾸세요.
     3. 공유기에서 외부 TCP `28541` → 이 PC의 내부 IP `28541`로 포워딩합니다.
     4. 화면에 `포트 전달 규칙이 있습니다`가 보이면 PC 쪽 준비가 끝났습니다.
3. `새 기기 연결` → `기기 종류`를 고르고 `QR 만들기`.
   - `Android 앱`: 휴대폰의 Own OpenCode 앱에서 `PC 추가` → `QR 스캔`(또는 링크 붙여넣기).
   - `다른 PC (데스크톱 앱)`: 화면의 `ownpc://…` 링크를 `복사`해 다른 PC로 보내고, 그 PC의 Own OpenCode 사이드바에서 `원격 PC 추가` → 붙여넣기. 기본 권한에 `파일`이 들어 있습니다. `터미널`은 이 PC에서 아무 명령이나 실행할 수 있어 기본으로 꺼져 있습니다. 필요하면 직접 고르세요(경고가 보입니다).
4. 앱에 확인 번호가 보이고, 이 PC에 `기기 연결 요청`(`Own 앱 · Android` 또는 `Own 데스크톱 앱 · Windows`)이 뜹니다. **번호가 같을 때만** `허용`합니다.
5. 다른 PC에서는 `원격 PC` 목록의 항목을 누르면 그 PC 전용 창이 열립니다. 창은 원격 PC의 화면을 그대로 보이므로 두 PC의 버전이 달라도 됩니다. 원격 창에서는 브라우저 패인·폴더 선택 대화상자 같은 데스크톱 전용 기능이 없습니다.

- 도메인·포트를 바꿔도 다시 연결할 필요가 없습니다. 앱이 접속할 때마다 새 경로를 받아 둡니다(인증서가 그대로인 동안).
- 앱 연결을 끄거나 기기를 폐기하는 방법은 11.4와 같습니다. 폐기된 앱에는 `이 기기의 연결이 만료되었거나 폐기되었습니다…`가 보입니다.
- DDNS 경로는 포트 하나를 인터넷에 엽니다. 기기는 이 PC에서 승인해야만 연결되지만, 확인 번호를 꼭 비교하세요. 이 경로로 들어온 접속은 기기 목록에 모두 `127.0.0.1`로 보입니다(포트 전달을 거치므로). 회사·공공 Wi-Fi가 그 포트를 막으면 Tailscale 경로를 쓰세요.
- 되돌리기: `앱 연결`의 `되돌리는 명령`(관리자 PowerShell)과 공유기 규칙 삭제, Tailscale 경로는 `tailscale serve --tcp=28540 off`.

**Android 앱 설치**

1. APK: `own\.out\build\<버전>\android\own-opencode-<버전>.apk`. 휴대폰으로 옮깁니다(USB, 클라우드 드라이브 등). 직접 빌드한다면 `own\scripts\build-desktop.ps1`을 먼저, `own\scripts\build-android.ps1`을 같은 `-Version`으로 나중에 돌립니다(데스크톱 빌드가 그 버전 폴더를 먼저 지우기 때문입니다).
2. 휴대폰에서 파일을 열고, 처음이면 그 앱(파일 관리자 등)에 `출처를 알 수 없는 앱 설치`를 허용합니다. Play 프로텍트 경고가 뜨면 `무시하고 설치`(스토어 앱이 아니라서 뜹니다).
3. 업데이트는 새 APK를 그대로 설치합니다. 이 PC의 개발용 서명 키로 빌드하므로 **같은 PC에서 빌드한 APK만** 덮어 설치됩니다.
4. 이번 버전의 알림은 앱이 열려 있을 때만 화면 안에 보입니다. 앱이 꺼져 있을 때 오는 푸시는 다음 단계입니다.

**모바일 미리보기 (휴대폰 없이 앱 화면 보기)**

데스크톱 앱에서 Android 앱이 보는 이 PC의 화면을 창 하나로 봅니다. 앱과 같은 연결(인증서 지문, 기기 토큰)을 이 PC 안에서만 쓰므로 설치할 것도, 방화벽 창도 없습니다. 설계는 [08 §4.3](08-app-access.md)에 있습니다.

1. `설정 > 기기`에서 게이트웨이와 `앱 연결`을 켭니다(Tailscale·DDNS 경로는 없어도 됩니다).
2. `모바일 미리보기` → 만료(7일 또는 30일) → `미리보기 기기 만들기`.
3. 바로 `기기 연결 요청`(`Own 모바일 미리보기 · Windows`)이 뜹니다. 섹션에 보이는 확인 번호와 같으면 `허용`합니다. 자동으로 허용되지 않습니다.
4. `열기`를 누르면 휴대폰 크기 창이 열립니다. 메뉴에서 기기 크기, `회전`(Ctrl+Shift+O), `키보드`(Ctrl+K, 화면 키보드가 올라온 높이), `뒤로`(Alt+←), `새로 고침`(F5), 라이트/다크, `개발자 도구`(F12)를 고릅니다.

- 기기 목록에는 `이 PC 미리보기` 표시가 붙은 앱 기기로 보입니다. 권한은 읽기·프롬프트·전환이고 터미널은 없습니다(목록의 `권한 바꾸기`로 바꿀 수 있습니다).
- 끝내려면 섹션이나 창 메뉴의 `지우기`(이 PC에서 폐기하고 창과 로그인을 지웁니다), 또는 목록에서 `폐기`합니다. `다시 만들기 필요`가 보이면(폐기, 만료, 인증서 변경) `다시 만들기`를 누릅니다.
- 이 창은 데스크톱 앱의 Chromium으로 그립니다. 앱 자체의 화면(PC 목록, QR 스캔)과 Android WebView·글꼴까지 보려면 Android Emulator나 실제 휴대폰을 씁니다. `own\scripts\android-emulator.ps1`은 필요한 준비를 알려 주고, 직접 켠 에뮬레이터에 APK 설치와 연결만 해 줍니다.
- 미리보기의 기기 토큰은 이 PC의 데스크톱 앱 데이터에 있습니다. 그 폴더가 복사되면 다른 경로로도 쓰일 수 있으니, 만료를 짧게 두고 쓰지 않을 때는 지우세요.

### 11.6 Tailnet Lock (브라우저 경로를 쓴다면 권장)

- 브라우저·홈 화면 앱(11.2)은 Tailscale이 발급한 인증서와, 어떤 기기가 tailnet에 속하는지 정하는 Tailscale 서버(control plane)를 믿습니다. 데이터는 Tailscale도 볼 수 없지만, Tailscale 서버가 침해되면 가짜 기기를 tailnet에 넣을 수 있습니다.
- **Tailnet Lock**을 켜면 새 기기는 사용자가 지정한 신뢰 기기의 서명을 받아야 들어옵니다. `설정 > 기기`의 `Tailscale` 줄에 상태가 보입니다(`Tailnet Lock 켜짐` / 꺼져 있으면 경고와 `Tailnet Lock 켜는 방법`).
- 켜는 방법은 Tailscale 문서(https://tailscale.com/kb/1226/tailnet-lock)를 따릅니다. 이 PC를 서명 기기로 넣고, 복구용 disablement secret을 안전한 곳에 보관합니다. own-open-code는 이 설정을 바꾸지 않습니다.
- 앱 연결(11.5)은 Tailnet Lock 여부와 관계없이 인증서 지문만 믿습니다. 그래도 기기 목록이 깨끗하도록 Tailnet Lock을 켜 두는 것을 권합니다.

## 14. 문제 해결

| 증상 | 할 일 |
|---|---|
| `서비스를 시작하지 못했습니다` | PowerShell에서 `own status`, `own start`로 오류를 봅니다. `own status`의 `exe`(설치된 버전 폴더의 `opencode.exe`, `app\current.json`이 가리킴)가 있는지, own 채널 빌드(`…-own.N`)인지 확인합니다. `2.0.18-own.2` 이하에서 `exe`가 `…\app\current\opencode.exe`면 2.7입니다. 서비스 로그를 봅니다(아래). 업데이트 직후라면 `own rollback`(2.4) |
| `Own OpenCode가 설치되지 않았어요` | 설치된 버전(`app\current.json`)이나 그 버전의 `web\index.html`이 없습니다. `own status`의 `installed`·`pointer_problem`을 봅니다. 설치 파일을 다시 실행합니다(2.2). `2.0.18-own.2` 이하를 설치한 PC면 2.7 |
| 설치 파일이 `own-open-code 서비스를 설치하지 못했습니다(종료 코드 …)` | `%LOCALAPPDATA%\own-open-code\install.log`의 마지막 `failed` 줄을 봅니다. 설치 파일이 실행한 명령과 종료 코드(PowerShell이 아예 뜨지 못한 경우 `error`)는 `%TEMP%\own-installer.log`에 있습니다. 이전 버전이 있었다면 그대로 돌고 있습니다. 고친 뒤 설치 파일을 다시 실행합니다 |
| 설치 파일이 `이 설치 파일이 다른 앱… 안에서 실행되었습니다`, 또는 `own`이 종료 코드 5 | Claude 데스크톱 앱의 터미널·에이전트처럼 `%LOCALAPPDATA%` 쓰기를 자기 폴더로 옮기는 앱 안에서 실행했습니다. 아무것도 바뀌지 않았습니다. 탐색기에서 설치 파일을 두 번 누르거나, 그 앱과 무관한 PowerShell 창에서 `own`을 실행합니다(2.7) |
| 조용히 설치(`/S`)한 뒤 `OWN_HOME`이 없고 `resources\own-payload`가 그대로 | 설치 파일이 아직 도는 중입니다(`/S`는 곧바로 돌아오고 서비스 부분은 마지막에 돕니다). `Start-Process -Wait`로 실행하고, 끝난 뒤 `%TEMP%\own-installer.log`를 봅니다(2.2) |
| 새 PowerShell 창에서 `own`을 찾을 수 없음 | 설치 뒤 새로 연 창인지 봅니다. 사용자 PATH(`[Environment]::GetEnvironmentVariable('Path','User')`)에 `%LOCALAPPDATA%\own-open-code\bin`이 있는지 봅니다. 없으면 설치 파일을 다시 실행합니다 |
| `앱 셸과 화면 버전이 맞지 않습니다` | 데스크톱 앱과 설치된 버전(`app\current.json`)이 다른 빌드입니다(서비스 업데이트를 미뤘거나 `own rollback` 뒤). `own status`의 `installed`와 같은 버전의 설치 파일을 실행합니다. 그동안은 `브라우저로 열기`(= `own open --browser`) |
| `서비스 버전(…)과 설치된 버전(…)이 다릅니다` 또는 `관리되지 않는 서비스 인스턴스입니다` | launcher 없이 뜬 서비스이거나 버전을 바꾼 뒤입니다. `설정 > 서버 연결 > 서비스 다시 시작`(데스크톱) 또는 `own restart`. launcher 밖에서 `opencode.exe serve`를 직접 실행하지 마세요 |
| `다른 버전의 서비스가 세션을 실행 중입니다` | 실행 중인 턴이 끝난 뒤 `own restart` |
| 방화벽 허용 창이 뜸 | 서비스, 게이트웨이, 원격 터널 끝점, 로그인 콜백은 모두 `127.0.0.1`입니다. LAN 접근은 필요 없으므로 허용하지 않아도 됩니다. 휴대폰 접근도 Tailscale serve를 거쳐 loopback으로 들어옵니다 |
| 브라우저 폴백에서 `페어링 링크가 필요합니다` | `own open --browser`를 다시 실행합니다(링크는 5분, 1회용) |
| 환경 변수의 API 키가 쓰이지 않음 | 설계입니다. launcher가 지웁니다. 앱에서 계정으로 추가합니다(4.1) |
| `이 프로젝트에 승인되지 않은 플러그인이 있어 계정 인증을 보내지 않습니다` | `설정 > 플러그인`에서 승인하거나 `own restart --untrusted` |
| `이 서비스에는 원격 호스트 기능(own-remote)이 없습니다` | `opencode.jsonc`의 `plugins`에 own-remote를 넣고 `own restart`(3장) |
| SSH 호스트가 `인증 필요` 또는 `호스트 키 확인 필요`에서 멈춤 | 배경 재연결은 비밀번호·모르는 호스트 키에서 멈춥니다. 호스트 `⋯` → `다시 연결` 또는 `호스트 키 확인…` |
| 연결 계정이 `이전 앱 갱신 대기` | 이전 앱에서 그 프로필을 한 번 엽니다. 자주 생기면 `이 앱으로 인수…`(4.3) |
| 연결한 키 계정이 `설정 오류` | 이전 앱에서 키가 지워졌거나 이 Windows 사용자로 열 수 없습니다. 이전 앱에서 키를 다시 저장하면 1분 안에 돌아옵니다 |
| OS 알림이 안 뜸 | 설치 파일로 설치한 앱에서만 안정적으로 뜹니다(시작 메뉴 바로가기 필요). `설정 > 데스크톱 > 테스트 알림`으로 확인합니다 |
| 휴대폰이 붙지 않음 | PC가 깨어 있는지, `설정 > 기기`의 게이트웨이가 `켜짐`인지(서비스를 launcher 없이 띄웠다면 데스크톱 앱을 한 번 엽니다), `tailscale serve status`에 `http://127.0.0.1:28539`가 있는지, 기기가 폐기·만료되지 않았는지 봅니다 |
| 게이트웨이가 `켜지 못했습니다 (포트 28539을(를) 다른 프로그램이 쓰고 있습니다)` | `포트`를 다른 값으로 바꿔 켜고, `tailscale serve` 명령도 그 포트로 다시 실행합니다 |

제거도 한 번에 합니다. 사용자 데이터는 따로 묻고, 기본은 **남깁니다**.

1. **원격부터 정리**(제거 프로그램은 PC 밖의 것을 지우지 못합니다)
   - 휴대폰: `설정 > 기기` → `모두 폐기`, 그리고 게이트웨이 `끄기`. `tailscale serve status`로 확인하고 `tailscale serve --https=443 off`로 끕니다.
   - SSH 호스트: 호스트마다 `⋯` → `제거…` → `원격 설치도 지우기`. 원격 세션 DB까지 지우려면 호스트에서 `~/.local/share/opencode/opencode-own.db*`, `~/.local/share/own-open-code/`, `~/.config/own-open-code/`, `~/.config/opencode/service-own.json`, `~/.local/state/opencode/service-own.json`을 직접 지웁니다. 안내된 API 키는 필요하면 교체합니다.
   - Claude 구독: 플러그인은 앱과 함께 지워지므로 따로 할 일은 없습니다. 로그인까지 지우려면 추가한 Claude 계정마다 `⋯` → `계정 빼기…`(`로그인 폴더도 지우기` 체크). 처음 연결한 계정의 로그인은 Claude Code 자신의 `%USERPROFILE%\.claude`이므로 이 앱이 지우지 않습니다. 세션 DB의 평문 토큰은 사용자 데이터를 지울 때 DB와 함께 지워집니다.
2. **제거**: Windows `설정 > 앱 > 설치된 앱 > Own OpenCode > 제거`. 제거 프로그램이 차례로 묻습니다.
   1. `own-open-code 서비스도 제거할까요?` — `예`(기본): 서비스를 멈추고 `app\`의 모든 버전, `bin\`(own 명령), 사용자 PATH 항목, `install.json`을 지웁니다. `아니요`: 데스크톱 앱만 지웁니다.
   2. `사용자 데이터도 삭제할까요? 되돌릴 수 없습니다.` — `아니요`(기본): 아래 표의 데이터가 남고, 다시 설치하면 그대로 쓰입니다. `예`: 표의 것을 모두 지웁니다.
   - 서비스에서 세션이 실행 중이면 그 전에 묻습니다. `아니요`면 아무것도 지우지 않고 끝납니다.
   - 데스크톱 앱 부분은 언제나 지웁니다: 설치 폴더, 시작 메뉴 바로가기, 알림 등록.
   - 조용히 제거: `"%LOCALAPPDATA%\Programs\own-desktop\Uninstall own-desktop.exe" /S`는 서비스를 지우고 데이터는 남깁니다. `--own-remove-data`를 더하면 데이터도, `--own-keep-service`면 서비스를 남기고, 세션이 실행 중이면 `--own-force`가 있어야 진행합니다.
3. 데스크톱 앱 없이 서비스만 지우려면 PowerShell에서 `own uninstall`(데이터 남김) 또는 `own uninstall --remove-data`.

**사용자 데이터**(`--remove-data` 또는 두 번째 질문에 `예`일 때만 지웁니다)

| 지울 것 | 내용 |
|---|---|
| `%LOCALAPPDATA%\own-open-code\` 전체 | 계정 레지스트리, vault(암호화된 키·토큰), 사용량 기록, DB 백업, 원격 호스트 상태, 기기 목록, `install.log` |
| `%USERPROFILE%\.config\own-open-code\` | 설정, 서비스 비밀번호 |
| `%USERPROFILE%\.config\opencode\service-own.json` | 이 파일 하나만. 폴더의 다른 파일은 upstream 것입니다 |
| `%USERPROFILE%\.local\state\opencode\service-own.json` | 이 파일 하나만 |
| `%USERPROFILE%\.local\share\opencode\opencode-own.db`, `-wal`, `-shm` | 세션 DB(Claude 슬롯의 평문 토큰 포함). `opencode` 폴더 자체는 upstream과 함께 쓰므로 지우지 않습니다 |
| `%APPDATA%\dev.own.opencode.desktop\` | 데스크톱 앱 데이터(제거 프로그램에서 `예`일 때. `own uninstall --remove-data`는 이 폴더를 건드리지 않습니다) |

- 드라이브 루트나 사용자 프로필 같은 폴더를 `OWN_HOME`·`OWN_CONFIG_DIR`로 바꿔 두었다면 그 폴더는 지우지 않고 알립니다. 폴더 안의 junction은 따라가지 않습니다(링크만 지움).
- 연결(`linked`)로 가져온 이전 앱의 로그인 파일은 own이 쓰지 않았으므로 그대로 남습니다. 인수한 프로필은 이전 앱에서 다시 로그인해야 할 수 있습니다.
- ChatGPT 로그인이나 API 키를 완전히 끊으려면 각 프로바이더 콘솔에서 세션을 끊거나 키를 폐기합니다.

## 16. 팀 모드 (T1–T3)

한 프로젝트를 몇 개의 **영역**으로 나누고, 영역마다 따로 작업 폴더와 **담당** 대화를 둔 채 **팀 메인** 대화가 일을 나눠 맡기는 기능입니다. 설계는 [06](06-team-worktrees.md)입니다. T1 빌드(`2.0.18-own.6`)에서는 새 프로젝트(또는 아직 작업 폴더가 없는 Git 프로젝트)에서 켜고 새 영역을 만들어 씁니다. T2부터는 이미 작업 폴더와 대화가 있는 프로젝트를 그대로 **받아들이고**(16.7), 영역 작업을 프로젝트 본 코드에 **반영하고**(16.8), **결정 기록**을 남깁니다(16.9). T3부터는 영역을 **끝내고**(16.10), **나누고 묶고**(16.11), 폴더 모양을 바꾸거나 대화를 옮기고(16.12), 큰 데이터 폴더를 영역끼리 **공유**하며(16.13), SSH 호스트의 프로젝트에서도 팀 모드를 씁니다(16.14). T3 빌드는 T3 종료 확인 뒤 `2.0.18-own.7`로 냅니다.

### 16.1 켜기

- 사이드바의 프로젝트 머리줄 `⋯` → `팀 모드 켜기…`(또는 프로젝트 줄의 `팀`, 대화 메뉴, 명령 팔레트). 작은 창에서 `무엇을 하려고 하나요? (선택)`에 할 일을 적고 `켜기`를 누릅니다(적지 않아도 됩니다). 할 일을 적었으면 켠 뒤 팀 메인 입력창에 상의 글이 들어가 있습니다(보내지 않음, 고친 뒤 보냄). 앱이 프로젝트를 살펴보고 LLM이 영역을 제안하면 규칙으로 검사한 뒤 요약 카드를 보입니다. 지우는 일이 없는 단계는 묻지 않고 하고, 끝나면 `되돌리기`가 있습니다.
- 팀 메인은 켠 대화의 계정·모델·추론 강도로 새로 만듭니다. 프리셋은 그 묶음의 ★입니다(켠 대화의 프리셋·울트라는 물려받지 않음).
- 새 영역 폴더는 메인 폴더 옆의 `<메인 폴더 이름>-team` 폴더에 만들고, 큰 파일 폴더는 처음에 받지 않습니다(필요하면 담당이 가져옵니다).
- 담당은 검사·설치 명령을 묻지 않고 실행합니다(켜기 카드와 `설정 > 팀`에서 끌 수 있음). 위험한 명령, 원격에 올리기, 작업 폴더 지우기는 언제나 묻습니다.

### 16.2 쓰기

- 일은 **팀 메인**에게 말합니다. 팀 메인이 영역의 담당에게 **메인 요청**을 보내고, 담당은 끝나면 보고합니다. 팀 메인은 보고가 오면 깨어나 다음을 정합니다.
- **상의하고 나누기**: “어떻게 나눌지 먼저 같이 정하자”라고 하거나 새 아이디어·큰 일이라 나누는 방법이 분명하지 않으면, 팀 메인이 영역을 만들기 전에 나누는 안(2–3개)을 보이고 답을 받은 뒤 만듭니다. “알아서 해”면 바로 나눕니다. 빈 팀 메인 대화의 `팀 메인에게 이렇게 말해 보세요` 예시는 누르면 입력창에 넣기만 합니다. 입력창에 다른 글(켜기 창의 상의 글, 직접 쓴 글)이 있는 동안에는 예시가 숨고, 입력창이 비면 다시 보입니다.
- **사용자 부탁**: 담당이나 동료 대화에서 팀 메인만 할 수 있는 일(새 영역, 나누기, 묶기, 끝내기, 대화 옮기기, 다른 영역에 맡길 일)을 말하면 담당이 그 말을 그대로 팀 메인에게 전합니다. 계획이 필요한 일은 팀 메인 대화에서 묻습니다.
- 담당 대화에 **직접 말해도 됩니다.** 사용자 말이 메인 요청보다 먼저입니다. 메인 요청은 그 폴더가 쉴 때 하나씩만 들어갑니다.
- **직접 작업**(2026-11-14): 담당 대화에 말하면 그 영역은 `직접 작업 중`이 되고, 메인의 새 요청은 내가 넘길 때까지 대기함에서 기다립니다(`직접 작업 중 · 요청 n개 기다림`). 그동안 담당의 보고(막힘도)는 팀 메인을 깨우지 않고 모았다가 넘길 때 한꺼번에 갑니다. 보고가 없었으면 팀 메인이 무엇을 할지 먼저 묻습니다. 내가 직접 고친 파일이나 메인 요청과 어긋나는 일은 담당이 그 대화에서 묻고, 반영은 내가 시킬 때만 합니다(팀 메인은 언제나 계획을 먼저 보임). 시간이 지나도, `다시 시작`을 눌러도 그대로이고, 담당 대화 위나 영역 메뉴의 `메인에게 넘기기`, 또는 “메인한테 넘겨”라는 말로만 끝납니다. 동료 대화에 말하는 것으로는 시작하지 않습니다. `설정 > 팀`의 `내가 영역에서 직접 일하면 메인은 기다리기`로 끌 수 있습니다.
- **메인 멈춤**: 담당 대화 머리줄의 스위치, 또는 영역 메뉴. 켜면 메인 요청이 들어가지 않고 기다립니다(`메인 멈춤 · 요청 n개 기다림`). 담당을 `■ 중단`으로 멈추면 메인 멈춤도 켜집니다(직접 작업 중일 때는 빼고). 프로젝트 메뉴 `모든 영역 멈추기` / `다시 시작`. 동료 대화나 같은 폴더의 다른 대화에서 오래 일할 때 씁니다.
- **영역과 역할**: 영역 수 제한은 없습니다. 팀 메인이 새 영역을 한 번에 5개 이상 만들 때만 계획을 먼저 보입니다. 팀 메인이나 담당에게 “이 영역이 보스 아이템 그림도 맡게 해 줘”처럼 말하면 영역의 역할을 바꿉니다(내가 정한 영역이면 계획). 같은 역할 안의 다음 일은 그 영역에 그냥 맡깁니다. 내가 정한 영역과 직접 작업 중인 영역에는 `끝낼 수 있음`이 붙지 않습니다. “보스 영역은 계속 둘 거야”처럼 말하면 이미 있는 영역도 `내가 정한 영역`이 되고(2026-11-17), 팀 메인이 있는 영역의 이름을 바꿔 다른 일에 다시 쓰면 역할도 함께 바꿉니다. 표시를 빼는 것은 계획을 먼저 보입니다.
- **길이**: 보고·영역 메시지·사용자 부탁은 20,000자까지 그대로 전해지고(팀 소식에는 앞부분만, 팀 메인은 전문을 읽음), 역할은 1,000자, 동료 역할과 담당 메모는 1,024자까지입니다. 넘으면 자르지 않고 알려 줍니다.
- **팀 지시문**: `설정 > 팀`의 `고급` > `팀 지시문`에서 팀 메인·담당·동료가 받는 지시문을 보고, `일하는 방식` 부분(역할마다 2,000자)을 고칩니다. 앱이 정한 부분은 보기만 합니다.
- **사이드바 팀 보기**: 메인 → 영역 → 팀에 넣지 않은 작업 폴더. 영역 행에 상태(`쉬는 중`, `작업 중`, `막힘`, `한도 대기 · 2시간 14분 후에 풀림` …), `모델: 팀과 같게 · 프리셋: …`, 데스크톱을 조작 중이면 `데스크톱 사용 중`이 보입니다. 위쪽 `승인 기다리는 것 n개`에서 여러 담당의 승인 요청에 한곳에서 답합니다. 그 아래 `팀 알림 n개`에는 팀이 알리는 것(프리셋 수리, 큰 파일 폴더 가져옴·그대로 둠, 팀 계정 옮김, 새 대화로 이어짐)이 보입니다. 수리 알림의 `고치기`는 그 프리셋을 편집기로 열고, `×`나 Delete 키로 알림을 닫습니다. T1 빌드에서는 알림이 그 창에만 있고 새로 고치면 사라집니다. T2부터는 아직 끝나지 않은 것(고치지 않은 프리셋, 기다리는 팀 계정 바꾸기, 멈춘 영역, 기다리는 반영, 고친 바로 가기 파일 사본)이 새로 고치거나 다른 창을 열어도 다시 보입니다.

### 16.3 영역의 모델과 프리셋, 팀 계정

- 영역의 모델(계정·모델·추론 강도)은 처음에 `팀과 같게`입니다(팀 메인을 따라감). 영역 메뉴 `모델 바꾸기…`로 다른 회사 구독·API 키·로컬 LLM이나 다른 모델을 고를 수 있습니다. 같은 회사의 다른 구독 계정(ChatGPT 01 팀에 ChatGPT 02)은 고를 수 없습니다.
- 영역 메뉴 `프리셋 바꾸기…`는 지금 담당 대화에 바로 적용됩니다(대화를 바꾸지 않음).
- **팀 계정 바꾸기**: 팀 메인 대화의 전환기에서 같은 회사의 다른 구독 계정을 고르면 `팀 전체(메인과 영역 n개)를 … 로 · … 일하는 중입니다 [끝나면 바꾸기] [멈추고 바꾸기]`가 뜹니다. 옛 계정의 일이 모두 끝나고 영역마다 인계 문서를 쓴 뒤 함께 옮기고, 영역은 새 계정의 새 대화로 이어 갑니다. 다른 길(담당 대화에서 바꾸기, 예약 전환)은 막혀 있습니다.

### 16.4 대화 바꾸기와 인계

- 담당 대화는 크기로 바뀌지 않습니다. 바뀌는 때: 팀 메인이 관련 없는 새 일로 보낼 때, 영역 메뉴 `새 대화로 이어가기`, 영역·팀의 계정 변경. 옛 담당이 인계 문서를 쓰고(쓸 수 없으면 앱이 만듦) 새 대화가 이어 받습니다. 옛 대화는 `지난 대화`로 남습니다. 받아들인 대화(16.7)를 아직 일을 맡기기 전에 바꿀 때는 그 대화에서 LLM을 돌리지 않고 앱이 인계 문서를 만듭니다.
- 팀 메인도 프로젝트 메뉴 `메인 새 대화`로 새로 시작할 수 있습니다.
- **담당 대화 바꾸기**(2026-11-12): 영역 폴더에서 직접 연 대화가 그 일을 더 잘 알게 됐으면 그 대화를 담당으로 삼을 수 있습니다. 그 대화의 `⋯`(사이드바 줄이나 영역 메뉴의 `팀과 이야기하는 대화` 묶음) → `이 대화를 담당으로` → `'게임 로직' 영역의 담당을 '충돌 판정 고치기' 대화(…)로 바꿀까요?`에서 `바꾸기`. 팀 메인에게 “게임 로직 담당을 충돌 판정 고치기 대화로 바꿔 줘”라고 해도 됩니다(계획을 보이고 답을 기다립니다).
  - 두 대화가 모두 쉴 때 바뀝니다(`지금 일이 끝나면 바꿔요`). 일하는 대화를 끊고 바꾸지 않으며, 기다리는 동안 `취소`하면 아무것도 바뀌지 않습니다.
  - 새 담당 대화는 자기 모델, 프리셋, 지금까지의 대화를 그대로 가지고 담당이 됩니다. 영역의 모델과 프리셋 표시도 그 대화의 것이 됩니다(`팀과 같게`였어도. 되돌리려면 `모델 바꾸기…`의 `팀과 같게`). 옛 담당에게 가려던 메인 요청은 새 담당에게 갑니다.
  - 옛 담당 대화는 지워지거나 보관되지 않고 보통 대화로 남습니다(`이 대화는 이제 담당이 아니에요`). 인계 문서를 쓰는 차례도 돌지 않습니다. `다시 담당으로`나 끝난 뒤 토스트의 `다시 …(으)로`로 되돌립니다.
  - 될 수 있는 대화: 그 영역 폴더의 대화, 그 영역의 동료, 전 담당. 안 되는 대화: 하위 대화, 팀 메인, 다른 폴더의 대화, 팀과 같은 회사의 다른 구독 계정을 쓰는 대화(그 대화의 계정을 바꾼 뒤 다시 고릅니다), 모델을 아직 고르지 않은 대화(`이 대화의 계정을 확인할 수 없어요. 모델을 고른 뒤 다시 해 주세요`).
  - 직접 작업 중인 영역은 바꾼 뒤에도 직접 작업 중이고, 새 담당 대화에 `메인에게 넘기기`가 보입니다. 메인 멈춤이 켜져 있던 영역은 바꾼 뒤에도 켜져 있습니다. 바꾼 뒤 `'게임 로직' 영역은 메인 멈춤이 켜져 있어요. 끄기 전에는 메인의 요청이 새 담당에게 가지 않아요` 알림이나 새 담당 대화 위의 `메인 멈춤 끄기`로 한 번에 끕니다.
  - 바꾸려는 순간에 옛 담당이 기다리던 요청을 막 받아 갔으면 바꾸지 않고 `옛 담당 대화가 그사이 요청을 받았어요. 그 일이 끝난 뒤 다시 해 주세요`라고 알립니다. 그 요청은 옛 담당이 하고, 끝난 뒤 다시 바꾸면 됩니다. 고른 대화가 받아 갔으면 `고른 대화가 그사이 요청을 받았어요. 그 일이 끝난 뒤 다시 해 주세요`입니다.
  - 동료를 담당으로 바꾸면 그 대화는 동료에서 빠지고 동료 역할 글도 지워집니다(확인 창이 알려 줍니다). 담당을 다시 바꿔도 동료로 돌아오지 않습니다. 자리를 내준 대화는 `⋯` → `동료로 등록…`으로 다시 동료로 둘 수 있습니다(`새 대화로 이어가기`로 물러난 대화는 안 됩니다).
  - **담당 메모**: 영역 메뉴의 담당 줄 `메모 바꾸기…`에 담당이 팀에서 맡은 일을 적어 둘 수 있습니다(1,024자까지). 영역에 동료가 있을 때 담당과 동료가 서로의 메모와 역할을 봅니다. 메모는 대화가 아니라 담당이라는 자리에 붙어 있어서 담당 대화를 바꿔도 남습니다.
  - **별칭**: 영역 메뉴 `설정` 묶음의 `별칭 바꾸기…`에서 담당에게 짧은 이름(예: `민지`, 12자까지)을 붙입니다. 팀의 다른 영역 이름·영역 id·별칭과 동료 이름과 겹치면(대소문자 구분 없음) 저장되지 않습니다. 비우면 지웁니다. 사이드바 영역 줄과 담당 대화의 머리줄에 `민지 · 화면`처럼 보이고, 좁은 화면에서는 영역 이름만 남습니다. 팀 메인에게 "민지에게 맡겨 줘"처럼 별칭으로 말해도 그 영역으로 갑니다(팀 메인의 팀 소식에 `민지 · 화면(ui)`로 보임). 별칭은 메모처럼 자리에 붙어 있어서 담당 대화를 바꾸거나 새 대화로 이어가도 남고, 담당 대화 자신의 역할 지시와 제목에는 들어가지 않습니다(담당이 자기 별칭을 모름).

### 16.5 큰 파일 폴더, 컴퓨터 사용, 휴대폰

- 영역 폴더는 처음에 큰 파일 폴더를 받지 않습니다. 담당이 필요하면 가져오고(`큰 파일 폴더 가져오기…`), 내려놓기는 따로 누를 메뉴가 없고 저절로 됩니다: 담당이 일을 끝냈다고 보고했을 때, 반영한 뒤, 새 대화로 이어 간 뒤 앱이 가져왔던 폴더를 내려놓습니다. 그 폴더에 정리되지 않은 파일(수정, 새 파일, 무시된 파일)이 하나라도 있으면 묻지 않고 그대로 둡니다(디스크만 씀). 메인 멈춤인 영역은 건너뜁니다.
- 담당이 어떤 턴에 큰 파일 폴더를 가져왔으면 그 턴 아래에 `이 턴에 큰 파일 폴더를 가져와서 변경 표시가 빠질 수 있습니다…`가 보입니다. 그 폴더 안에서 바뀐 파일은 그 턴의 변경 목록에 나오지 않을 수 있고, 그 턴 앞으로 되돌려도 그대로 남을 수 있습니다. 앱이 담당 폴더를 따라 대화를 옮겼으면 그 대화 위에 `이 대화는 옮기기 전 지점으로 되돌릴 수 없습니다`가 보입니다.
- **컴퓨터 사용은 팀이 켜지 않습니다.** 대화마다 사용자가 켜고(세션 `⋯`), 팀 메인이나 팀 소식이 시작한 턴에서는 켜져 있어도 컴퓨터를 쓰지 않습니다. 같은 대화에서 사용자가 직접 시킨 일은 됩니다.
- 휴대폰(게이트웨이)에서는 팀 보기, 상태, 메인 멈춤, 담당과의 대화가 됩니다. T2부터는 반영 카드를 보고 `결정 적기`도 됩니다. 확인 단계, 원격 저장소에 올리기, `설정 > 팀` 쓰기는 PC에서만 하고, 기기에는 `<PC 이름>에서 확인하세요`가 보입니다.

### 16.6 끄기와 되돌리기

- 프로젝트 메뉴 `팀 모드 끄기`. 대화, 영역 폴더, 기록은 그대로 두고, 기다리던 메인 요청은 보내지 않습니다(다시 켜도 되살리지 않음). 영역 폴더 지우기는 늘 묻는 단계입니다. 다시 켜면 같은 팀으로 이어 갑니다.
- T3부터 끄기 대화상자에 `끝난 영역 정리하고 끄기`가 있습니다. 모두 반영되고 깨끗한 영역(16.10의 "끝낼 수 있음"에서 7일 조건만 뺀 것)을 한꺼번에 끝내고, 폴더 지우기를 **한 번에** 묻고(`끝난 영역 3개 정리(7.5 GB)`), 답한 뒤 팀 모드를 끕니다. 일하는 중인 영역은 건너뜁니다. `두기`로 남긴 폴더는 끌 때 앱의 잠금도 풀립니다.
- 켜기 같은 큰 작업은 요약 카드의 `되돌리기`로 되돌립니다. `설정 > 팀`: 영역 수 기본 상한, `반영하기 전에 묻기`(T2, 16.8), 담당이 묻지 않고 실행할 명령, 확인 기준, `결정 기록을 프로젝트에 남기기`(T2, 16.9), 다른 도구 작업 폴더 경로 패턴.

### 16.7 진행 중인 프로젝트 받아들이기 (T2)

- 이미 작업 폴더(git worktree)와 대화가 있는 프로젝트에서 `팀 모드 켜기`를 누르면, 앱이 작업 폴더마다 무엇이 진행 중인지 보고 LLM 제안을 검사한 뒤 **있는 작업 폴더를 그대로 영역으로 받아들입니다.** 요약 카드: `영역 3개: cl-cu · cl-perf · cl-siwc. 지금 있는 작업 폴더를 그대로 씁니다.` · `기존 대화는 그대로 두고, 메인이 일을 맡길 때 담당 역할을 붙입니다.`
- **받아들여도 바뀌지 않는 것**: 폴더의 파일, 기록(줄기), 저장하지 않은 변경, 따로 치워 둔 변경, 그 폴더의 대화(지시, 도구, 프리셋, 승인 모드, 컴퓨터 사용 허용). 폴더는 지금 자리에 둡니다. 앱은 영역 폴더를 잠가(지우기 막이) 다른 프로그램의 정리가 지우지 못하게 하고, 이름 없는 작업 상태의 저장 지점은 지켜 둡니다.
- **담당은 그 폴더의 가장 최근 대화**입니다. 영역의 메인과 프리셋도 그 대화의 것 그대로이고, 대화가 길어도 그대로 이어 씁니다. 팀 메인이 그 영역에 **처음 일을 맡길 때** 그 대화에 담당 역할과 팀 도구를 붙입니다(그때 한 번 대화 끝에 안내가 붙고 앞부분 캐시는 그대로입니다). 그 전까지 그 대화는 사용자의 것과 똑같습니다.
- **예외: 같은 회사의 다른 구독.** 그 대화가 팀 메인과 같은 회사의 다른 구독 계정(예: 팀은 ChatGPT 01, 그 대화는 ChatGPT 02)을 쓰면 카드에 `cl-perf 대화는 ChatGPT 02를 씁니다. 메인이 일을 맡길 때 ChatGPT 01로 새 대화에서 이어 갑니다 [이 영역 빼기]`가 보입니다. 처음 일을 맡길 때 앱이 인계 문서를 만들어(ChatGPT 02로는 아무것도 보내지 않음) 팀 계정의 새 대화로 이어 가고, 옛 대화는 사용자의 `지난 대화`로 남습니다. 같은 ChatGPT 로그인의 Codex·Sign in with ChatGPT 계정은 한 구독이라 그대로입니다. 계정을 판단할 수 없으면 앱은 그 폴더를 받아들이지 않거나(켤 때) 그 요청을 기다리게 합니다(처음 맡길 때).
- **팀에 넣지 않은 작업 폴더**: 받아들이지 않은 작업 폴더는 팀 보기 아래 `팀에 넣지 않은 작업 폴더 n`에 남습니다. 폴더 행의 `[팀에 넣기]`로 나중에 넣을 수 있고(묶음 머리줄의 `[팀에 넣기]`는 묶음을 펼칩니다), 넣은 것도 카드의 `되돌리기`로 되돌립니다. 다른 도구(Claude, Codex 등)가 만든 작업 폴더와 경로에 `#`이 있는 폴더는 앱이 건드리지 않습니다.
- **팀에서 빼기**: 영역 메뉴 `팀에서 빼기` → `폴더, 기록 이름과 대화는 그대로 둡니다. 기다리던 메인 요청은 보내지 않습니다.` 붙였던 담당 역할과 팀 도구만 떼고 잠금을 풉니다.
- **밖에서 바꾼 것 따라가기**: 영역 폴더에서 사용자가 다른 기록으로 바꾸거나 폴더를 옮기면 앱이 따라가고 `팀 알림`에 알립니다(`'cl-perf' 영역이 다른 기록으로 바뀌어 따라갔어요`, `'cl-perf' 폴더가 옮겨져 따라갔어요`). 폴더를 찾을 수 없거나 정보가 맞지 않으면 그 영역은 `찾을 수 없음`·`멈춤(폴더 정보 불일치)`이 되고 메인 요청을 보내지 않습니다. 고치면 저절로 풀립니다.
- 팀이 켜진 프로젝트에서 새 작업 폴더가 필요하면 `새 워크트리` 대신 **`새 영역`**(이름, 할 일)을 고릅니다.

### 16.8 반영하기 (T2)

- 영역의 작업을 **프로젝트 본 코드**(대상 줄기, 보통 `main`)에 넣는 것이 **반영**입니다. 담당이 `반영 준비됨`을 보고하면 팀 메인이 반영하거나, 사용자가 영역 메뉴 `이 영역 반영하기`를 누릅니다.
- **무엇이 들어가나**: 담당이 준비됐다고 한 시점의 작업까지만 들어갑니다. 그 뒤 저장 지점은 넣지 않고 카드에 `그 뒤 저장 지점 n개는 넣지 않았어요`가 붙습니다(메뉴로 반영할 때 준비 표시가 없으면 지금 끝을 씁니다).
- **어떻게**: 앱이 작업 폴더를 꺼내지 않고 합친 결과를 만들고, 앱 전용 검사 폴더(`<메인 폴더 이름>-team\.verify`)에서 팀의 검사 명령(예: `bun run typecheck`)을 돌린 뒤, 통과하면 프로젝트 본 코드를 앞으로 보냅니다. 카드: `인벤토리 화면 반영하는 중 · 검사 1/2` → `… 프로젝트 본 코드에 반영했습니다 [되돌리기] [원격 저장소에 올리기…] [자세히]`. 담당 대화에도 같은 카드가 입력창 위에 보입니다(`닫기`까지).
- **묻지 않고 반영합니다**(처음 값). 검사를 통과한 것만 들어가고 `되돌리기`가 있기 때문입니다. 반영 전에 확인하고 싶으면 `설정 > 팀`의 `반영하기 전에 묻기`를 켭니다(그러면 카드에서 `반영하기`를 눌러야 들어갑니다).
- **기다릴 때**: 메인 폴더에서 같은 파일을 고치고 아직 저장 지점에 넣지 않았으면 `메인 폴더(own-open-code)에서 아직 저장 지점에 넣지 않은 파일 2개와 겹칩니다. 그 변경을 저장 지점에 넣거나 되돌린 뒤 [다시 반영]을 누르세요`. 그 폴더에서 기록 정리(rebase 등)가 진행 중이면 끝난 뒤 저절로 다시 반영합니다. 앱은 사용자의 변경을 지우거나 덮어쓰지 않습니다.
- **겹치면**: `프로젝트 본 코드의 새 변경과 겹쳐서 담당에게 정리를 맡겼습니다`. 담당이 정리하고 다시 준비됐다고 하면 다시 반영합니다. 두 번째로 겹치거나 검사가 실패하면(`검사가 실패해서 반영하지 않았습니다 [로그 보기]`) 팀 메인이 깨어나 정합니다.
- **되돌리기**: 프로젝트 본 코드가 그 반영 그대로일 때 카드의 `되돌리기`로 되돌립니다. 그 사이 만든 저장 지점은 지켜 두고 알립니다. 그 뒤 본 코드가 더 바뀌었으면 `메인에게 되돌리기 맡기기`가 보입니다.
- **원격에 올리기**: 저절로 올리지 않습니다. `원격 저장소에 올리기…`·`검토 요청 올리기…`가 원격 이름, 기록 이름, 실행할 명령을 보이고(기본 포커스 `취소`), `올리기`를 눌러야 PC에서 올립니다. 로그인이 필요하면 `원격 저장소에 로그인이 필요합니다. 터미널에서 한 번 로그인해 주세요`가 뜹니다.
- **큰 파일 검사**(T3): 팀에 큰 파일 폴더와 큰 파일 검사 명령(예: 엔진의 에셋 가져오기·검사)이 있고 반영할 변경이 큰 파일 폴더를 건드리거나 담당이 반영 준비를 알리며 엔진 실행이 필요하다고 했으면(큰 파일 폴더를 건드리지 않은 변경이라도), 앱 전용 전체 폴더 `<메인 폴더 이름>-team\.assets`에서 그 검사를 돌린 뒤에만 반영합니다. 이 폴더는 처음 한 번 만들 때 디스크·내려받기 크기가 확인 기준(`설정 > 팀`)을 넘으면 묻습니다(`큰 파일 검사용 폴더 …(을)를 만듦(디스크 …)` → `확인하기…`). `두기`를 고르면 그 반영은 하지 않고 팀 메인에게 이유가 전해집니다. 그 폴더에는 사용자 작업이 없고, 메인 폴더와 영역 폴더는 검사에 빌려 쓰지 않습니다. 엔진으로 그 폴더를 열어 커밋하거나 고쳤어도 지우지 않고 지켜 둡니다(`자세히`의 기록). 검사가 필요 없으면 카드에 `큰 파일 검사는 건너뜀`입니다.

### 16.9 결정 기록 (T2)

- 팀 메인이 정한 것(예: "필드 이름은 snake_case")을 **결정 기록**으로 남깁니다. 사용자도 프로젝트 메뉴 `결정 적기`(제목, 내용)로 적을 수 있고, `결정 기록 4번을 적었습니다`처럼 번호가 붙습니다. 대화상자 아래에 지금까지의 기록이 최신순으로 보입니다.
- 기록은 저장소의 git 폴더 안 팀 기록 폴더(`.git\own\team\…\decisions\0004-….md`)에만 둡니다. 작업 폴더 밖이라 반영할 때 겹치지 않고 정리 명령이 지우지 않습니다. 사용자가 적은 기록은 팀 메인을 깨우지 않고 다음 팀 소식에 실리며, 새 영역을 나눌 때 LLM이 최근 기록 제목을 참고합니다.
- 프로젝트에도 남기고 싶으면 `설정 > 팀`의 `결정 기록을 프로젝트에 남기기`를 켭니다. 그러면 팀 메인이 메인 폴더의 `docs/decisions/`에 사본을 저장 지점으로 넣습니다(앱이 직접 쓰지 않음).

### 16.10 영역 끝내기 (T3)

- 다 끝난 영역은 영역 메뉴 `영역 끝내기…`로 정리합니다. `'cl-perf' 영역을 끝낼까요?` · `기록 이름과 대화는 남습니다. 기다리던 메인 요청은 보내지 않습니다. 폴더는 지우기 전에 목록과 크기를 보이고 다시 묻습니다`.
- **무엇이 일어나나**: 이름 없는 작업 상태의 저장 지점을 먼저 지켜 두고, 기다리던 메인 요청을 취소해 팀 메인에게 목록을 알리고, 담당 대화를 `지난 대화`로 둔 뒤 영역을 끝낸 것으로 적고, 마지막에 **폴더 지우기를 묻습니다**. 기록 이름(줄기)과 대화는 지우지 않습니다.
- **폴더 지우기 대화상자**: 지워지는 것(다시 만들 수 있는 캐시·설치 결과·빌드 결과, 큰 것부터 크기와 합계), 남는 것(기록 이름, 대화. 반영하지 않은 작업이 있으면 `반영하지 않은 저장 지점 n개는 기록에 남습니다`), `자세히`에 명령. 기본 포커스는 `두기`입니다. `.env` 같은 작은 설정 파일은 지우지 않고 팀 기록 폴더(`.git\own\team\…\retired\<영역>\`)로 옮겨 둡니다. 무시된 파일 중 다시 만들 수 없는 것(예: 손으로 넣은 데이터 폴더)은 목록에 `다시 만들 수 없음`으로 따로 표시합니다. 확인한 뒤에 폴더 안이 바뀌었으면 지우지 않고 새 목록으로 다시 묻습니다.
- **지우지 않는 경우**: 저장하지 않은 변경(수정, 새 파일, 고친 바로 가기 사본)이 있거나, 안에 다른 저장소·작업 폴더가 있거나, 그 폴더에서 대화·셸·터미널이 돌고 있으면 폴더를 지우지 않고 카드에 이유를 남깁니다. Windows에서 다른 프로그램이 폴더를 쓰고 있으면 `다른 프로그램이 폴더를 쓰고 있습니다. 그 프로그램을 닫은 뒤 다시 시도하세요`이고, 다시 하면 남은 것을 확인한 목록 안에서만 정리합니다. `두기`를 고르면 폴더는 그대로 두고, 나중에 `영역 끝내기…`를 다시 고르면 지우기만 묻습니다.
- **끝낼 수 있음**: 고유한 작업이 모두 프로젝트 본 코드에 들어갔고, 깨끗하고, 7일 동안 변경이 없는 영역은 사이드바 영역 행에 `끝낼 수 있음`이 붙고 팀 메인 위에 `제안: '로그인' 영역을 끝낼 수 있습니다(모두 반영됨, 7일 동안 변경 없음) [끝내기…] [무시]`가 뜹니다. 앱은 스스로 끝내지 않습니다. `[무시]`는 그 창에서만 숨깁니다.
- 폴더가 사라진 영역(`찾을 수 없음`)의 행에는 `[다시 만들기] [끝내기]`가 있습니다. `[다시 만들기]`는 그 영역의 기록(마지막 저장 지점)에서 새 폴더와 새 담당 대화로 영역을 다시 만듭니다(같은 이름, 영역 메뉴의 `다시 만들기…`도 같음). 찾을 수 없는 영역은 그대로 남으니 필요 없으면 `[끝내기]`로 지울 것 없이 끝냅니다. 영역 묶기를 되돌리려는데 그 뒤 묶인 영역에 새 저장 지점이 생겨 되돌릴 수 없으면, 결과 카드가 묶여 들어간 영역을 그 기록으로 `[다시 만들기]` 할 수 있다고 알려 줍니다. 사이드바의 `작업 폴더 정리`로 영역 폴더를 지우려 하면 `영역 끝내기…`로 안내합니다.
- 영역이 일하는 중이면 끝내기는 그 일이 끝날 때까지 기다리고, 카드에 이유를 보입니다(예: `'cl-perf': 실행 중인 명령이 끝나기를 기다립니다`). 대화 옮기기와 묶기도 같습니다.

### 16.11 나누기와 묶기 (T3)

- **나누기**(`나누기…`, 이름·할 일): 한 영역의 일이 커졌을 때 지금 작업에서 시작하는 새 영역을 만듭니다. 원래 영역의 담당이 인계 메모를 쓰고, 새 영역의 담당은 그 메모와 같은 메인·프리셋으로 시작합니다. 원래 영역은 그대로이고 팀 메인이 일을 다시 나눠 맡깁니다. 되돌리기는 새 영역을 끝내는 것입니다.
- **묶기**(`영역 묶기…`, 묶을 영역 고르기): 고른 영역의 작업을 이 영역으로 합치고, 고른 영역의 인계 메모와 기다리던 메인 요청을 이 영역으로 옮기고, 고른 영역의 담당 대화는 `지난 대화`로 둡니다. 고른 영역의 폴더는 지우기 전에 다시 묻습니다(16.10의 대화상자). 기록 이름은 남습니다.
  - 고른 영역에 저장하지 않은 변경이 있으면 묶기가 그 담당에게 커밋을 한 번 청하고 기다립니다. 담당이 저장 지점에 넣으면 묶기가 이어지고, 그래도 변경이 남으면 `… 담당이 변경을 커밋하지 않았습니다 … 커밋한 뒤 다시 묶으세요`로 멈춥니다. 담당 대화가 없는 받아들인 폴더면 앱이 그 변경을 저장 지점으로 만들지 묻습니다(파일은 그대로, 확인한 뒤 다시 묶기를 고름).
  - 두 영역의 변경이 겹치면 이 영역의 담당에게 정리를 맡기고 멈춥니다.
  - **되돌리기**: 이 영역이 아직 묶은 그대로일 때만 되돌립니다(그 사이 생긴 저장 지점은 지켜 둠). 그 뒤 이 영역이 더 바뀌었으면 되돌릴 수 없습니다.
- 팀 메인도 나누기·묶기·끝내기·변환을 제안하고 할 수 있지만, 메인 멈춤이거나 일하는 중인 영역은 건너뛰고 카드에 적습니다(`'cl-perf'(은)는 메인 멈춤이라 이번 정리에서 건너뛰었어요`). 팀 메인도 건너뛴 것을 말해 주고, 카드의 `다시 하기`를 누르면 그 일을 사용자 동작으로 다시 합니다(그 영역이 쉴 때까지 기다리고, 그동안 다른 반영은 기다림). 폴더 지우기와 큰 내려받기는 언제나 사용자가 확인합니다.
- **팀 구성 다시 보기…**(프로젝트 메뉴): `어떻게 바꾸고 싶나요? (선택)`에 바라는 것을 적고 `제안 받기`를 누르면 팀 메인이 지금 팀을 살펴보고(`메인이 팀 구성을 살펴보는 중…`) 항목마다 체크 상자와 한 줄을 보입니다. 고른 항목만 `고른 n개 적용`으로 사용자 동작으로 합니다. 끝내기는 처음에 체크되어 있지 않고(`되돌릴 수 없어요`), 일하는 중이거나 메인 멈춤인 영역의 일도 체크 없이 보이며 고르면 그 영역이 쉴 때까지 팀의 다른 일(메인 요청, 반영)도 기다립니다. 확인이 필요한 것은 `· 확인한 뒤 해요`, 하지 않는 것은 `하지 않음: <이유>`로 보입니다. `팀 메인과 상의하기`는 제안(`무시`로 닫은 제안은 빼고)을 팀 메인 입력창에 넣습니다. 결과 카드의 `되돌리기`로 되돌립니다(끝내기만 한 카드는 되돌리기가 없음).

### 16.12 파일 모양 바꾸기, 대화 옮기기 (T3)

- **파일 모양 바꾸기**: 영역 메뉴에서 `가벼운 폴더(큰 파일 제외)로` 또는 `전체 폴더로`.
  - 전체 → 가벼운 폴더: 담당은 먼저 새 대화로 이어 가고(대화 크기와 관계없이, 바뀌는 파일이 많기 때문), 큰 파일 폴더를 이 영역에서 내려놓습니다. 그 폴더에 저장하지 않은 변경이 있으면 하지 않고, 다시 만들 수 있는 파일만 있으면 지우기 전에 목록과 크기를 보이고 묻습니다(이때 `두기`를 골라도 담당은 이미 새 대화입니다).
  - 가벼운 → 전체 폴더: 내려받을 크기와 디스크 크기를 먼저 보이고 묻습니다. 대화는 그대로입니다.
- **대화 옮기기**(`대화 옮기기…`): 다른 대화를 이 영역의 폴더로 옮겨 그 폴더에서 이어 갑니다. 사용자만 할 수 있고(팀 메인은 제안만), 팀 메인·담당·하위 에이전트 대화는 옮길 수 없습니다. 옮긴 대화는 옮기기 전 지점으로 되돌릴 수 없고 대화 위에 그 안내가 보입니다. 되돌리기는 다시 옮기는 것입니다.

### 16.13 공유 폴더 (T3)

- 데이터셋이나 모델 가중치처럼 git이 추적하지 않는 큰 **읽기 전용** 폴더가 메인 폴더에 있으면, 팀 모드를 켤 때 LLM이 그 폴더를 영역끼리 공유하자고 제안할 수 있습니다(도구 캐시는 제외).
- 공유하려면 원본을 읽기 전용으로 바꿔야 하므로 **한 번 묻습니다**: `'weights' 폴더를 읽기 전용으로 바꿈(쓰기와 지우기를 막고 읽기는 그대로)` · 되돌리는 법(Windows: 그 폴더의 속성 > 보안 > 고급에서 이 사용자의 거부 항목을 지움, Linux: 쓰기 권한을 다시 줌), 명령은 `자세히`에. `두기`를 고르면 공유하지 않습니다.
- 확인하면 모든 영역의 같은 자리에 원본을 가리키는 링크(Windows junction, Linux symlink. 관리자 권한·개발자 모드 불필요)를 만들고, git이 그 링크를 보지 않게 저장소의 `.git\info\exclude`에 한 줄을 더합니다. 새 영역도 링크를 받습니다. 정리 명령(`git clean -fdx`)이 링크를 지우면 다음에 앱이 다시 만듭니다. 그 자리에 진짜 폴더나 다른 링크가 있으면 건드리지 않고 팀 알림으로 알립니다.
- 영역을 끝내거나 켜기를 되돌릴 때 링크는 원본을 따라가지 않고 링크만 지웁니다. `rm -rf weights/`처럼 끝에 `/`를 붙인 삭제는 링크를 따라가므로, 원본을 읽기 전용으로 두는 것이 그 사고를 막습니다.

### 16.14 원격(SSH) 호스트의 팀 (T3)

- SSH 호스트(10장)의 프로젝트에서도 `팀 모드 켜기`가 됩니다. 팀은 그 호스트의 서비스 안에서 돌고 영역 폴더도 그 호스트에 만듭니다. 사이드바·메뉴·카드는 이 PC의 팀과 같습니다.
- **큰 파일(Git LFS) 저장소**: 호스트에 git-lfs가 없어도 됩니다. 켜기가 큰 파일 도구가 없다고 하면 앱이 이 PC의 설치판에 든 고정 버전 git-lfs를 SSH로 그 호스트의 `~/.local/share/own-open-code/tools/git-lfs/`에 **한 번** 올리고(sha256 확인, sudo 없음, `~/.gitconfig`는 그대로) 켜기를 다시 합니다. 실패하면 `원격 호스트에 큰 파일 도구를 준비하지 못했습니다: …`. 그 저장소에는 저장소 안 설정(`git config --local`)으로 큰 파일 필터를 걸고, 그 뒤에만 영역과 담당을 만듭니다(그래서 담당이 커밋해도 큰 파일이 포인터로 들어감). 호스트 셸의 PATH에는 다음 서비스 다시 시작부터 들어갑니다(호스트 상태가 `설정 대기`).
- 원격 저장소에 올릴 때도 큰 파일을 먼저 올리고 실패하면 올리지 않습니다(16.8).
- 휴대폰·다른 기기에서도 원격 팀을 보고 메인 멈춤과 대화를 할 수 있고, 확인 단계는 이 PC에서만 합니다. 팀이 확인을 기다리거나 반영이 실패하면 서비스의 알림 목록(피드)에 그 팀 메인 대화를 가리키는 항목이 쌓입니다(그 목록을 보여 주는 휴대폰 화면은 아직 없음).
- 원격 팀의 영역 프리셋은 그 호스트로 옮겨진 이 PC의 프리셋입니다(5.5). 원격 호스트에서는 컴퓨터 사용을 쓸 수 없습니다.

### 16.15 팀 룸

- 팀 메인이나 담당·동료 대화를 보는 동안 오른쪽 작업 패널에 `팀 룸` 탭이 생깁니다(팀 밖의 대화에는 없음). 끝나지 않은 영역마다 작은 캐릭터 하나가 책상과 컴퓨터 앞에 앉아 있고, 머리 위 이름표에 별칭과 영역 이름이 보입니다(좁으면 영역 이름만).
- 캐릭터의 생김새(옷·머리 색, 모자·헤드폰·안경, 책상 색, 화면 빛, 책상 위 물건)는 영역마다 정해져 있어서 다시 열어도 같습니다. 그림 파일을 받지 않고 앱 안에서 그립니다(네트워크 요청 없음).
- 동작이 영역의 상태를 보여 줍니다: 담당이 일하면 자판을 두드리고, 쉬면 앉아 있고, 오래 조용하거나 한도를 기다리거나 메인 멈춤이면 졸고(`z`), 허락이나 질문으로 사용자를 기다리면 손을 들고(`?`), 문제가 생기면 몸이 붉어지고 땀방울이 납니다(`!`).
- 캐릭터나 이름표를 누르면 그 영역의 담당 대화가 열립니다.
- 방은 패널 크기에 맞춰 크게 그려집니다. 세로로 긴 패널이나 휴대폰에서는 자리가 여러 줄로, 넓은 패널에서는 옆으로 늘어서고, 패널 크기나 영역 수가 바뀌면 다시 맞춥니다. 이름표는 패널 밖으로 나가지 않습니다.
- 탭이 보이고 창에 초점이 있을 때만 움직입니다(초당 30번까지). 다른 탭이나 다른 창으로 가면 멈춥니다. Windows의 `애니메이션 효과`를 끄면(움직임 줄이기) 멈춘 그림으로 그립니다. 3D를 그릴 수 없는 기기에서는 같은 이름표가 목록으로 보입니다.

## 17. 다른 도구의 대화 (Codex, Claude Code)

프로젝트 폴더에서 **Codex**나 **Claude Code**로 나눈 대화를 own이 이 PC 안에서 찾아 읽기 전용으로 보여 주고, 원하면 own 대화로 옮겨 이어 가게 합니다. 설계는 [09](09-session-import.md)입니다. IMPORT 단계의 기능이라 다음 릴리스부터 들어갑니다(`2.0.18-own.N` 설치본에는 없음).

### 17.1 찾기

- **어디서 찾나.** Codex는 `CODEX_HOME`(없으면 `%USERPROFILE%\.codex`), Claude Code는 `CLAUDE_CONFIG_DIR`(없으면 `%USERPROFILE%\.claude`)입니다. 예전 앱의 프로필 폴더처럼 다른 곳에 있는 저장소는 `설정 > 다른 도구 > 찾을 곳 더하기`로 더합니다(이 PC의 창에서만).
- **어느 대화가 보이나.** 그 대화의 작업 폴더가 프로젝트 폴더와 같거나 그 아래인 것입니다. 프로젝트 폴더는 own이 그 프로젝트로 기록한 폴더(같은 저장소의 다른 clone도 own에서 연 적이 있으면 포함)와 그 폴더들의 연결 작업 폴더(`git worktree list`)입니다. 폴더 이름을 바꾸거나 옮겼으면 목록의 `모든 폴더`에서 찾아 `이 폴더로 가져오기`를 씁니다.
- **들어가는 곳.**
  - 사이드바에서 프로젝트를 펼치면 목록 끝에 `다른 도구의 대화 · 새 N개`가 보입니다. N은 아직 가져오지 않은 대화 수이고, 다 가져오면 사라집니다. 끄려면 `설정 > 다른 도구 > 사이드바에 보이기`(이 창에만 적용).
  - 프로젝트 머리줄 `⋯` → `다른 도구의 대화…`(Git이 아닌 폴더에도 있음), 명령 팔레트 `다른 도구의 대화 열기`.
  - 그 폴더의 빈 새 대화 화면에 `이 폴더에 아직 가져오지 않은 Codex·Claude Code 대화 N개가 있습니다 · 보기`가 한 번 보입니다.
- **목록.** 최근 것부터 50개씩입니다. 줄마다 제목, 첫 요청 한 줄, 도구, 마지막 활동, `원래: <모델>`이 보이고 줄 끝에 `열기`와 `이어서 하기`가 있습니다. 거르기는 `전체 / Codex / Claude Code`, `이 폴더 / 모든 폴더`, `더 보이기`(하위 에이전트, 보관됨, 자동 실행). 검색 상자는 제목을 찾고, `내용까지`를 켜면 사용자와 모델의 글도 찾습니다(도구 출력은 찾지 않음, `일부만 찾음 · 계속 찾기`).
- **표시.** `가져옴`(이미 옮긴 대화. 원본이 그 뒤로 길어졌으면 `원본에 새 턴 N개`), `진행 중일 수 있음`(그 도구가 2분 안에 쓴 대화. 가져오면 지금까지만), `폴더 없음`(원래 작업 폴더가 지워짐. 가져오면 프로젝트 폴더로), `읽을 수 없음`(이유와 함께), `다른 컴퓨터`(Claude Desktop의 SSH 원격 세션).
- **Claude Code는 30일 지난 기록을 지웁니다**(처음 설정). 아직 가져오지 않은 Claude Code 대화가 지워지기 7일 안으로 남으면 줄에 `N일 뒤 원본이 지워질 수 있음`이 붙습니다(그 전에는 줄의 툴팁에만). own은 저절로 옮겨 두지 않습니다(자동 보관 없음, 2026-10-08 결정). 남겨 두려면 지워지기 전에 `이어서 하기`로 가져오세요. 그때 `자세히`의 `원래 대화 전체도 own에 저장`(처음 켬)을 켜 두면 모델이 보지 않는 앞부분도 own 대화에 남습니다. 원본이 지워진 뒤에는 own에 저장한 것만 남습니다.

### 17.2 읽기 전용으로 보기

- `열기`를 누르면 그 대화가 own의 대화 화면처럼 보입니다. 맨 위 띠 `읽기 전용 · <도구> 대화 · 원본 파일은 바꾸지 않습니다`, 머리에 도구와 버전, 원래 모델, 폴더, 브랜치, 기간, 턴 수, 크기(약 N 토큰), 압축 횟수.
- 도구 호출(실행한 명령, 바꾼 파일의 diff)이 보이고, 그 도구가 압축한 자리에 `<도구>가 여기서 대화를 압축했습니다`(`요약 보기`)가 있습니다. Codex의 원격 압축은 요약이 암호화되어 있어 `요약 내용을 읽을 수 없음(암호화) · 그 앞의 사용자 요청 N개는 남아 있음`으로 보입니다.
- 오른쪽 `개요`에 턴 목록이 있습니다. 큰 압축 파일(`.jsonl.zst`)은 앞에서부터 풀어 읽으므로 개요 끝에 한동안 `읽는 중…`이 보입니다.
- `Ctrl+F`는 그 대화 전체(도구 출력 포함)에서 찾고, 결과를 누르면 그 턴으로 갑니다. `텍스트로 복사`, `원본 위치 열기`(데스크톱 앱)도 있습니다.
- 보기는 LLM을 부르지 않으므로 사용량이 들지 않고, 대화 내용이 PC 밖으로 나가지 않습니다. API 키·토큰·개인키처럼 보이는 값은 `[redacted:API key]`처럼 가려서 보입니다(원본은 그대로).

### 17.3 이어서 하기 (own 대화로 옮기기)

목록 줄이나 보기의 `이어서 하기`, 또는 보기에서 사용자 메시지의 `여기까지 이어서 하기`(그 턴까지만)를 누르면 대화상자가 열립니다. 이미 가져온 대화면 먼저 `열기` / `새로 가져오기`를 묻습니다(다시 가져오면 언제나 새 대화이고 앞서 가져온 대화는 그대로).

1. **이어 갈 모델**: `[계정][모델][추론 강도]`. 원래 도구와 같은 회사의 계정이 있으면 그것이 처음 값이고 `원래와 같은 회사`가 붙습니다(Codex → ChatGPT, Claude Code → Claude 구독). 없으면 그 폴더의 새 대화와 같습니다. 옆에 `원래: <모델>`과 `이 모델 창의 N%`가 보입니다. `추천`은 표시일 뿐이고, 사용량이 모자라면 남은 사용량이 넉넉한 계정을 목록으로 보일 뿐 own이 계정을 바꾸지 않습니다.
2. **방식**
   - `그대로 이어가기`: 대화를 그대로 옮깁니다. 모델은 원래 모델이 마지막에 보던 것을 봅니다(그 도구가 압축했다면 그 요약과 그 뒤). LLM 호출이 없고, 첫 메시지에 그 부분이 캐시 없이 한 번 전송됩니다. 고른 모델의 창에 들어갈 때, 그리고 Codex 원격 압축 대화는 언제나 처음 값입니다.
   - `요약해서 이어가기`: 창에 들어가는 만큼 최근 대화를 원문으로 두고 들어가지 않는 앞부분만 요약합니다. `이어 갈 모델로 요약`(비용 표시, 숨긴 보조 대화에서 own의 보통 압축으로 한 번)이나 `LLM 없이`(무료: 그 도구의 요약, 프로그램이 뽑은 사실, 사용자 요청 목록). 창에 들어가지 않을 때의 처음 값입니다.
   - 줄마다 비용(요약, 첫 요청, 이후 요청마다)이 보이고, 고를 수 없는 줄은 흐리게 이유가 붙습니다. 창에 들어가는 대화를 가볍게 시작하고 싶으면 `그대로` 가져온 뒤 평소처럼 `압축`을 누릅니다.
3. **가져올 위치**: 처음 값은 그 대화의 마지막 작업 폴더(와 브랜치)입니다. 목록을 연 폴더와 다르면 `<폴더>에서 이어가기`로 바꿀 수 있습니다.
4. **자세히**: `여기까지(턴 N)`, `원래 대화 전체도 own에 저장`(처음 켬), `비밀 가리기(N개)`(처음 켬).
5. **전송 안내**: 버튼 위에 늘 "첫 메시지와 함께 약 N 토큰이 <계정>(<회사>)으로 전송됩니다"가 보입니다. LLM 요약이면 지금 요약하려고 보낼 양도 보입니다. 원래 도구와 다른 회사의 계정이면 `다른 회사`가 붙습니다.
6. **실행**: `가져오기`(LLM 요약이면 `요약하고 가져오기`). `원본 읽는 중` → `요약 중` → `대화 만드는 중`이 보이고 `취소`할 수 있습니다(대화를 만들기 시작한 뒤에는 취소할 수 없음). 대화상자를 닫아도 계속되고 끝나면 알림이 뜹니다. 새로 고쳐도 다시 열면 진행이 보입니다. 한 번에 하나만 가져옵니다.
7. **결과**: 새 own 대화가 열리고 머리에 `Codex에서 가져옴`(누르면 원본, 가져온 때, 방식, 요약 모델, 가린 값 수, `원본 보기`), 첫 화면에 "Codex 대화 41턴을 가져왔습니다 · 요약에서 이어갑니다" 한 줄이 보입니다. 그 뒤는 보통 대화와 같습니다(압축, 계정 전환, 프리셋).
- **실패하면** 이유와 다른 길(`LLM 없이 마치기`, 들어가면 `그대로 이어가기`, `다른 계정 고르기`)이 보입니다. own은 저절로 다시 하거나 다른 계정으로 돌리지 않습니다. 원본이 그사이 바뀌었으면 다시 계획합니다.
- **대화 내용이 PC 밖으로 나가는 때는 둘뿐입니다**: `이어 갈 모델로 요약`을 실행할 때(그 계정으로, 설정 `agents.compaction.model`이 요약 모델을 바꿨으면 그 모델로. 대화상자에 보임)와, 가져온 대화를 이어 갈 때(첫 메시지부터 모델이 보는 부분).

### 17.4 다른 도구의 파일은 읽기만 합니다

- 쓰지도, 옮기지도, 지우지도, 잠그지도 않습니다. Codex의 SQLite DB는 제자리에서 열지 않고 own 임시 폴더(`OWN_HOME\tmp\import-…`)에 복사한 사본을 읽은 뒤 바로 지웁니다.
- 로그인 파일(`auth.json`, `.credentials.json`)은 열지 않고, `codex`나 `claude` 프로그램을 띄우지 않습니다.
- own이 남기는 것은 `OWN_HOME\state\import-sources.json`(더한 찾을 곳)과 `OWN_HOME\state\import-index.json`(파일 경로·크기·시각·작업 폴더 같은 색인. 대화 내용, 제목은 넣지 않음)뿐입니다. 제목과 미리보기는 메모리에만 둡니다.

### 17.5 통계와 사용량

- 가져온 대화는 own의 사용 통계(활동 열지도, 모델별 집계)에 **원래 날짜의 활동으로 그대로 셉니다**(2026-10-08 결정). 모델 묶음은 `codex-cli`·`claude-code`로 따로 보이고 토큰·비용은 0입니다. 통계에서 빼는 설정은 없습니다.
- `이어 갈 모델로 요약`이 쓴 사용량은 그 계정의 사용량 기록(한도·사용량 화면의 계정별 기록)에만 남습니다. 요약에 쓴 보조 대화는 끝나면 지우므로 통계에는 들어가지 않습니다.
- 가져온 대화의 첫 요청은 own이 계정마다 재는 시스템·도구 크기 측정에 쓰지 않습니다(옮긴 기록이 실려 있어 측정이 부풀기 때문).

### 17.6 휴대폰·다른 기기

- 기기(11.3)의 권한으로: `읽기`가 있으면 목록·보기·검색, `프롬프트`도 있으면 `이어서 하기`까지 됩니다(2026-10-08 결정. 휴대폰 기본은 둘 다 켬). 보기에 보이는 비밀은 가려져 있습니다.
- `찾을 곳`(설정 > 다른 도구)은 이 PC의 창에서만 바꿉니다.
- SSH 원격 호스트(10장)에는 이 기능이 없습니다. own은 이 PC에 있는 Codex·Claude Code 기록만 읽습니다.

### 17.7 잘 안 될 때

- **사이드바 줄이 안 보임**: 그 폴더의 아직 가져오지 않은 대화가 0개이거나, `사이드바에 보이기`를 껐거나, 프로젝트 머리줄 `⋯`에도 항목이 없으면 서비스에 own-import가 없는 것입니다(`opencode.jsonc`의 `plugins` 맨 끝에 `own-import` 줄이 있어야 합니다. 지운 줄은 업데이트가 다시 넣지 않습니다).
- **찾는 대화가 없음**: 대화를 시작한 폴더가 이 프로젝트의 폴더가 아닐 수 있습니다. 목록의 `모든 폴더`를 보거나, 다른 곳에 있는 저장소면 `찾을 곳 더하기`를 씁니다. 처음 여는 목록은 `아직 찾는 중입니다…`로 시작하고 찾는 대로 채워집니다.
- **`읽을 수 없음`**: `원본 파일이 없습니다`(Codex가 지웠거나 옮김), `형식을 읽을 수 없습니다`, `own이 읽지 않는 위치입니다` 등. 원본은 그대로이고 다른 대화는 계속 보입니다.
