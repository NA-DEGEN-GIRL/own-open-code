# 29. 확장 만들기: creator 모드

**한 줄 요약** — 대화의 에이전트를 `creator`로 바꾸고 "이런 기능이 있으면 좋겠어"라고 말하면, 모델이 own에 더할 **확장**을 만들어요. 확장은 대부분 코드가 아니라 own이 읽는 설정이라서, 만들고 고치고 끄고 되돌리는 일이 모두 한 번에 돼요. 앱을 다시 시작할 필요도 없어요. 코드가 꼭 필요한 도구는 따로 도는 **MCP 서버**로, 요청을 고치는 일은 **코드 플러그인**(기본 꺼짐)으로 만들 수 있어요.

> **용어** 확장: own에 더하는 작은 기능 묶음이에요. 지시문 조각, 명령을 감싼 도구, 도구 규칙, 재시도 정책, 압축 지시, 에이전트, 슬래시 명령, 스킬, 내 지시문을 담을 수 있어요.

## 무엇이 되나요?

- **지시문 조각**: "커밋 메시지는 영어로", "답은 한 문장으로" 같은 글을 모든 대화(또는 고른 에이전트 방식·에이전트·모델·프로젝트)에 넣어요.
- **명령 도구**: "이 프로젝트의 테스트를 파일 하나만 돌리는 도구"처럼 명령 하나를 도구로 만들어요. 실행할 때는 보통 셸 명령처럼 승인 모드를 따라요.
- **도구 규칙**: "이 프로젝트에서는 웹 가져오기 금지", "`git push`는 꼭 물어보기"처럼 도구를 막거나 묻게 해요.
- **재시도 정책**: 모델 요청이 실패했을 때 다시 시도하는 횟수와 기다리는 시간을 줄여요.
- **압축 지시 추가**: 자동 압축이 요약할 때 꼭 남길 것("열린 TODO 목록은 그대로")을 더해요.
- **에이전트, 슬래시 명령, 스킬**: 리뷰 전용 하위 에이전트, `/changelog` 같은 명령, 필요할 때 읽는 스킬을 만들어요.
- **내 지시문**: Codex·Pi·DeepSeek 방식의 고칠 수 있는 지시문을 확장으로 바꿔요. 끄면 원래 쓰던 글로 돌아가요.
- **MCP 서버**: 명령 하나로는 안 되는 도구("이 CSV를 읽어 표로 정리하는 도구")를 코드로 만들어요. own의 샌드박스(브라우저 같은 WebAssembly 안)에서 돌아서, 프로젝트 파일과 미리 정한 주소 말고는 아무 데도 닿지 않아요 — 앱·계정·디스크에 손대지 못해요.
- **코드 플러그인**: 모든 요청이나 압축 요청을 코드로 고쳐요. 샌드박스가 없어서(서비스 안에서 나로 돌아요) 위험이 커요 — 기본으로 꺼져 있어요.

## creator 모드 쓰기

1. 새 대화를 열고 입력창 옆의 에이전트를 `creator`로 바꿔요.
2. 만들고 싶은 것을 말해요. 예: "이 저장소에서 `bun test 파일`을 돌리는 도구를 만들어 줘", "push 전에는 꼭 물어보게 해 줘".
3. 모델이 먼저 지금 있는 것(에이전트, 명령, 스킬, 확장)을 살펴보고, 확장을 써서 검사해요.
4. 확장을 저장하기 전에 **확장 바꾸기 승인** 카드가 떠요. 카드에는 확장이 하는 일이 줄마다 적혀 있어요. `허용`을 누르면 바로 적용돼요.
5. 다른 대화에서 바로 써 봐요. 조각은 다음 메시지부터, 도구는 다음 단계부터 보여요.

> **참고** 승인 모드가 `전체 허용`이면 카드 없이 저장돼요. `읽기 전용`에서는 확장을 바꿀 수 없어요. creator 모드의 도구는 creator 대화에만 있어서, 다른 대화의 요청과 캐시는 그대로예요.

## 설정 > 확장

`설정` > `고급` > `확장`에서 만든 확장을 모두 봐요. 이 PC의 창에서만 보여요(휴대폰·다른 PC에서는 안 보여요).

| 보이는 것 | 뜻 |
|---|---|
| `켜짐` · `꺼짐` | 지금 적용되는지예요. 스위치로 켜고 꺼요. 꺼도 판과 기록은 그대로예요 |
| `적용 안 됨` | 판을 읽을 수 없거나 다른 확장과 이름이 겹쳐요. `문제` 줄에 이유가 있어요 |
| `파일이 바뀜` | 저장된 판의 파일을 누군가 고쳤어요. 그 판은 적용되지 않아요. 다른 판으로 되돌려요 |
| `판 N` | 지금 쓰는 판이에요. 고칠 때마다 새 판이 생겨요 |
| `하는 일` | 항목마다 종류, 이름, 캐시에 주는 영향 |
| `적용 범위` | `모든 프로젝트`가 기본이에요. `폴더 더하기`로 프로젝트 폴더를 넣으면 그 폴더와 그 안에서만 적용돼요. `모든 프로젝트로`가 되돌려요 |
| `판 기록` | 판마다 만든 시각, 만든 쪽(`creator 모드`·`나`), 메모. `내용 보기`로 그 판의 파일을, `이 판으로 되돌리기`로 그 판을 다시 써요 |
| `지우기` | 한 번 더 `정말 지우기`를 눌러야 지워져요. 지운 확장은 보관 폴더의 휴지통에 최근 20개까지 남아요 |

- 내 지시문이 든 확장은 언제나 모든 프로젝트에 적용돼요(내 지시문은 에이전트 방식마다 하나예요).
- 되돌리기는 파일을 다시 쓰지 않고 쓰는 판만 바꿔요. 그래서 빠르고, 예전 판이 그대로 남아요.

## 코드가 필요한 도구: MCP 서버

creator 모드에 "이건 명령으로 안 되니 코드로 만들어 줘"라고 하면 MCP 서버 확장을 만들어요.

1. 모델이 서버 코드와 시험을 쓰고 `확장 바꾸기 승인` 카드를 띄워요. 카드에 “코드가 own의 WebAssembly 샌드박스에서, 환경·프로세스·디스크 없이 돌아요”가 적혀 있어요. 필요한 라이브러리가 있으면 “의존성 설치” 줄도 보여요. 라이브러리는 own이 정한 목록 안에서만 정확한 판으로 고를 수 있고, 설치할 때는 `전체 허용`에서도 꼭 물어요.
2. `허용`을 누르면 own이 저장하기 전에 검사해요: 라이브러리 설치(설치 스크립트 없이), 타입 검사, 확장이 가져온 시험, 모델처럼 도구를 불러 보는 시험. 하나라도 실패하면 아무것도 저장하지 않고, 쓰던 판이 그대로 남아요. 모델이 실패 이유를 읽고 고쳐요.
3. 통과하면 바로 다른 대화에서 쓸 수 있어요. 도구는 Code Mode 도구라서 열린 대화의 캐시를 깨지 않아요.

부를 때는 언제나 물어요:

| 승인 모드 | MCP 서버의 도구를 부를 때 |
|---|---|
| `묻기`, `읽기 전용` | 부를 때마다 물어요 |
| `전체 허용` | 판마다 처음 한 번만 물어요. 새 판이 생기면 다시 한 번 물어요 |

- 서버는 그 대화의 프로젝트 폴더에서 돌고, 그 폴더 안의 파일만 읽고 쓸 수 있어요. own의 보관 폴더, 보관함, 로그인 파일에는 닿지 않아요.
- 서버 코드는 own의 WebAssembly 샌드박스에서 돌아요. 환경 변수·프로세스·디스크가 아예 없고, 나가는 길은 own이 주는 두 가지뿐이에요: 대화의 프로젝트 폴더 안 파일(밖으로 나가는 경로, 링크, `.ssh`·`.git`·보관함 같은 자격 증명 폴더는 거절), 그리고 확장이 미리 적고 사용자가 승인한 주소로의 네트워크 요청. 그래서 API 키·토큰에 닿을 길이 없어요.
- 읽기 전용 역할(둘러보기, own 리뷰)은 MCP 서버 도구를 아예 부를 수 없어요. 메인 대화에서 쓰세요.
- 확장 카드의 `멈추기`로 서버를 바로 멈추고, `다시 시작`으로 다시 켜요. `로그 보기`에서 서버가 언제 시작하고 끝났는지, 남긴 글, 저장 전 검사 결과를 봐요.

## 코드 플러그인 (기본 꺼짐)

코드 플러그인은 모든 요청이나 압축 요청을 코드로 고치는 확장이에요. 지시문 조각이나 MCP 서버로 안 되는 일에만 써요.

> **주의** 코드 플러그인은 서비스 프로세스 안에서 나(사용자)로 돌아요. 판마다 직접 승인한 것만 켜지지만, 승인하면 그 코드가 내 파일과 네트워크에 다 닿고 계정 토큰·키·자격 증명을 읽어 밖으로 보낼 수 있어요. own은 샌드박스로 막지 않아요(그건 MCP 서버가 해요). 게다가 저장 전 검사도 이 코드를 돌리니, 돌리기 전에 먼저 한 번 묻고, 켜려면 판마다 또 승인해야 해요. 믿을 수 있는 코드일 때만 켜세요.

1. `설정` > `고급` > `확장` 맨 위의 `코드 플러그인 쓰기`를 켜요. 꺼져 있으면 creator 모드가 코드 플러그인을 만들 수 없어요.
2. creator 모드가 만든 판은 저장 전에 검사를 거쳐요: 타입 검사, 확장의 시험, 정해진 요청으로 돌려 보는 시험, 같은 요청에 늘 같은 결과를 내는지와 캐시를 깨지 않는지 보는 시험.
3. 저장된 판은 `승인 기다림`이에요. 카드의 `이 판 승인`을 눌러야 켜져요. 새 판이 생기면 다시 승인해야 해요. `승인 거두기`로 언제든 내려요.
4. 코드 플러그인은 모든 프로젝트에 적용돼요(폴더로 좁힐 수 없어요).

- 플러그인이 오류를 내면 그 프로젝트 폴더에서만 꺼지고 앱은 계속 돌아요. 카드에 `이 폴더에서 멈춤`이 보이고, 고친 뒤 `다시 켜기`를 눌러요.
- 스위치를 끄면 불러온 코드 플러그인도 모두 내려가요.
- 앱을 새 판으로 올리면 예전 판으로 만든 코드 플러그인은 `다시 만들어야 함`이 돼요. creator 모드에 다시 만들어 달라고 해요.

## 넓히는 규칙은 내가 승인해요

도구 규칙 가운데 `allow`(묻지 않고 허용)는 안전장치를 넓혀요. 그래서 모델이 만들어도 바로 켜지지 않아요.

1. `설정` > `확장`의 그 확장 카드에 `넓히는 규칙(allow)이 승인을 기다려요`가 보여요.
2. 내용을 확인하고 `넓히는 규칙 승인`을 눌러요. 이 판의 allow만 켜져요.
3. 확장을 고쳐 새 판이 생기면 다시 승인해야 해요. `승인 거두기`로 언제든 끌 수 있어요.

- `deny`(막기)와 `ask`(묻기)는 좁히기만 해서 승인 없이 바로 적용돼요. `ask`는 `전체 허용`에서도 물어요.
- 어떤 확장도 승인 모드의 막기(`읽기 전용`의 편집 막기 등)와 own 자신의 안전장치는 풀지 못해요.
- 승인한 `allow`도 own이 따로 묻는 것은 풀지 못해요: GitHub에 쓰기, 이미지 만들기, 팀 모드의 위험한 git 명령은 그대로 물어요.

## 캐시에 주는 영향

| 항목 | 열린 대화의 캐시 |
|---|---|
| 지시문 조각, Code Mode 도구, 스킬 | 그대로예요. 바뀐 내용이 대화 뒤에 붙어요 |
| 도구 규칙, 재시도 정책 | 요청 글이 그대로예요 |
| 압축 지시 추가 | 압축 요청에만 붙어요 |
| MCP 서버(Code Mode) | 그대로예요 |
| 코드 플러그인 | 대화 뒤에 더하기만 하면 그대로예요. 앞부분을 바꾸는 플러그인은 승인 카드에 캐시 경고가 붙어요 |
| 직접 도구(`direct`), 하위 에이전트 | 열린 대화의 캐시가 한 번 깨져요 |
| 내 지시문 | `내 지시문`을 쓰는 대화의 캐시가 한 번 깨져요 |

명령 도구는 기본으로 Code Mode 도구예요. creator 모드에 "직접 도구로"라고 따로 말할 때만 직접 도구가 되고, 승인 카드에 “열린 대화의 프롬프트 캐시가 한 번 깨져요”가 적혀요.

## 안전

- 선언 확장은 코드를 실행하지 않아요. 명령 도구가 실행하는 것은 승인 모드가 허용한 명령뿐이에요.
- MCP 서버는 own의 WebAssembly 샌드박스에서 돌고(프로젝트 파일과 선언한 주소만), 부를 때마다 승인 모드대로 물어요. 읽기 전용 역할은 아예 못 불러요. 코드 플러그인은 스위치를 켜고, 돌리기 전과 켜기 전에 각각 승인해야만 돌아요.
- 명령 도구에는 비밀 변수(API 키, 토큰 등)가 전달되지 않고, 출력에 보이는 토큰 모양 글은 가려져요. 보관함이나 로그인 파일을 가리키는 명령은 저장되지 않아요.
- 확장 파일은 `OWN_HOME\creator`에 있어요. 에이전트의 파일 도구는 이 폴더를 고칠 수 없고, 누가 고쳐도 그 판은 `파일이 바뀜`이 되어 적용되지 않아요.
- SSH 원격 호스트는 확장의 읽기 전용 사본만 받아요. 호스트에서는 확장을 만들거나 바꾸거나 승인할 수 없고, 호스트가 이 PC의 확장을 고칠 길도 없어요. 아래 "SSH 원격 호스트"를 보세요.

## SSH 원격 호스트

확장은 연결한 SSH 원격 호스트([22장](22-ssh-remote.md))에도 가요. 확장은 이 PC에서만 만들고 바꾸고 승인해요. 호스트는 읽기 전용 사본을 받아 그 호스트의 대화에 적용해요.

- **무엇이 가나요?** 지시문 조각, 도구 규칙, 재시도, 압축 지시, 에이전트·명령·스킬, 내 지시문, 명령 도구, MCP 서버가 가요. 이 PC에서 `켜짐`인 확장의 지금 판만 가요.
- **명령 도구**는 호스트의 셸에서 돌고, 그 호스트 대화의 승인 모드대로 물어요.
- **MCP 서버**는 호스트에서도 own의 샌드박스 안에서 돌아요. 호스트가 받은 파일의 해시를 이 PC의 판과 맞춰 본 뒤, 호스트에서 시험과 smoke를 샌드박스 안에서 다시 돌려요. 통과해야 켜져요. 부를 때 묻는 것도 호스트 대화에서 해요(`전체 허용`의 판마다 첫 승인도 호스트에 남아요).
- **코드 플러그인**은 이 PC 전용이에요. 카드의 호스트 줄에서 `<호스트>에서 이 판 허용`을 눌러야만 그 호스트로 가요. 이 허용은 이 PC의 `이 판 승인`과 따로이고, 위험도 같아요: 그 코드가 호스트의 서비스 안에서 나로 돌아요. 호스트도 판 폴더의 해시를 다시 확인한 뒤에만 불러와요.
- **넓히는 규칙(allow)**도 호스트마다 따로 허용해요. 이 PC에서 `넓히는 규칙 승인`을 했어도, 그 호스트의 줄에서 `<호스트>에서 이 판 허용`을 누르기 전에는 호스트에서 꺼져 있고 호스트는 평소처럼 물어요. 허용하면 그 호스트의 대화도 규칙이 넓힌 일을 묻지 않고 해요.
- **적용 범위**: 확장 카드의 `SSH 호스트`에서 `호스트 폴더 더하기`로 호스트의 폴더(예: `/home/me/work`)를 범위에 넣어요. 범위가 비어 있으면 모든 호스트의 모든 프로젝트에 가요. 이 PC의 폴더만 넣으면 호스트에는 가지 않아요.
- **보낼 호스트**: `모든 호스트`, `고른 호스트만`, `고른 호스트 빼고` 가운데 골라요.
- **어느 호스트에 있나요?** 카드의 호스트 줄에 `보냄`, `빠짐`, `범위 밖`, `PC 전용`과 호스트가 알려 온 상태(`호스트에서 켜짐`, `호스트에서 적용 안 됨`)가 보여요. 허용을 거두거나 호스트를 뺐는데 호스트가 아직 맞추지 못했으면 `호스트에 아직 켜져 있어요`가 보여요. 호스트가 이 PC와 다시 이어져 맞추면 빠져요.
- 되돌리기·끄기·지우기는 이 PC에서 하면 호스트에도 그대로 따라가요. 호스트의 사본을 손으로 고치면 그 호스트에서 `파일이 바뀜`이 되고, 다음 동기화 때 이 PC의 판으로 다시 받아요. 호스트와 연결이 끊겨도 호스트는 마지막으로 받은 사본을 그대로 써요. 다만 이 PC와 호스트의 own 판이 달라 서로 맞출 수 없을 때는 호스트가 코드 플러그인과 넓히는 규칙만 먼저 꺼요.

## 문제가 생기면

| 증상 | 할 일 |
|---|---|
| 에이전트 목록에 `creator`가 없어요 | 앱이 최신인지 확인해요. `설정` > `플러그인`의 기본 기능에 own.creator가 있어야 해요 |
| 저장했는데 다른 대화에 안 보여요 | 카드가 `켜짐`인지, `적용 범위`에 그 프로젝트가 들어 있는지 확인해요. 조각은 그 대화의 다음 메시지부터 보여요 |
| `적용 안 됨`이에요 | `문제` 줄을 읽어요. 다른 확장과 도구 이름이 겹치면 한쪽을 꺼요 |
| `파일이 바뀜`이에요 | `판 기록`에서 다른 판으로 되돌리거나, creator 모드에 고쳐 달라고 해요 |
| allow 규칙이 안 먹어요 | `넓히는 규칙 승인`을 눌렀는지 확인해요. 새 판에는 다시 승인해야 해요 |
| 명령 도구가 계속 물어요 | 승인 모드를 따라요. `항상 허용`을 누르면 그 명령은 그 프로젝트에서 다시 묻지 않아요 |
| MCP 서버 도구가 계속 물어요 | `묻기`에서는 부를 때마다 물어요(`항상 허용`도 넘지 못해요). `전체 허용`에서는 판마다 처음 한 번만 물어요 |
| MCP 서버를 만들다 실패했어요 | 저장 전 검사가 실패한 거예요. 쓰던 판은 그대로예요. `로그 보기`에 단계마다 결과가 있어요. creator 모드에 고쳐 달라고 해요 |
| creator 모드가 코드 플러그인을 못 만든대요 | `코드 플러그인 쓰기`가 꺼져 있어요. 위험 설명을 읽고 필요할 때만 켜요 |
| 코드 플러그인이 `승인 기다림`이에요 | 카드의 `이 판 승인`을 눌러요 |
| `이 폴더에서 멈춤`이 보여요 | 그 폴더에서 플러그인이 오류를 냈어요. creator 모드에 고친 판을 만들게 하거나, 그대로 `다시 켜기`를 눌러요 |
| 호스트 대화에 확장이 안 보여요 | 카드의 호스트 줄을 봐요. `범위 밖`이면 호스트 폴더를 더하고, `빠짐`이면 `보낼 호스트`를 바꿔요. 호스트와 연결돼 있어야 새 판이 가요 |
| 호스트 줄이 `호스트에서 적용 안 됨`이에요 | 옆에 이유가 있어요. MCP 서버면 호스트의 시험이 실패한 거예요. 이 PC의 `로그 보기`가 아니라 호스트의 `OWN_HOME/creator/logs`에 단계마다 결과가 있어요 |
| 코드 플러그인이 호스트에서 안 돌아요 | `PC 전용`이면 그 호스트에서 이 판을 허용하지 않은 거예요. 위험 설명을 읽고 필요할 때만 허용해요 |
