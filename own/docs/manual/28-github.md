# 28. GitHub 연결: 여러 계정

**한 줄 요약** — GitHub 계정을 여러 개 연결해 두고 프로젝트·팀 영역·대화마다 어느 계정을 쓸지 골라요. 어느 에이전트 방식이든 GitHub 도구(저장소·PR·이슈·Actions 읽기, 허용하면 PR 만들기·댓글)를 쓰고, 에이전트와 팀 모드의 `git push`·`git pull`도 고른 계정으로 로그인해요. 토큰은 이 PC의 보관함에만 있어요.

> **용어** 토큰(personal access token): GitHub가 내 계정 대신 쓰라고 내주는 긴 비밀 글자예요. 세분화 토큰(`github_pat_`로 시작)은 저장소와 권한을 골라서 만들 수 있어요.

## 무엇이 되나요?

- **GitHub 도구**: 대화에서 "이 PR 검토해 줘", "이슈 목록 보여 줘", "Actions 실패 로그 봐 줘"처럼 말하면 에이전트가 GitHub 도구로 읽어요. 도구는 GitHub가 만든 공식 MCP 서버의 도구 그대로예요. 결과 맨 위에 “GitHub account: octo-work (회사)”처럼 어느 계정으로 했는지 적혀요.
- **쓰기는 묻고 나서**: 계정에 쓰기를 허용하면 PR 만들기, 댓글, 파일 고치기 같은 쓰기 도구도 보여요. 어느 에이전트·승인 모드에서든 쓸 때마다 승인 카드가 떠요. `항상 허용`은 그 도구와 그 저장소, 그 계정에만 적용돼요.
- **git 로그인**: 에이전트·팀 모드가 실행하는 `git push`·`git pull`·`git clone`이 GitHub에 로그인해야 할 때, 그 폴더에 고른 계정의 토큰을 own이 건네요. 내 `~/.gitconfig`는 그대로예요.
- **여러 계정**: 회사 계정과 개인 계정을 같이 연결해 두고, 회사 프로젝트는 회사 계정, 오픈소스 폴더는 개인 계정처럼 나눠 써요.

## 토큰 만들기 (세분화 토큰 권장)

1. GitHub에 계정으로 로그인한 브라우저에서 `설정` > `GitHub` > `계정 추가`의 `GitHub에서 토큰 만들기`를 눌러요(GitHub의 Settings > Developer settings > Fine-grained tokens 페이지가 열려요).
2. 이름과 기한을 정하고, **Resource owner**를 고르고(개인 계정 또는 조직 하나), **Repository access**에서 쓸 저장소만 골라요.
3. 권한(Permissions)은 필요한 만큼만 줘요.

| 하려는 일 | 줄 권한 |
|---|---|
| 읽기만(코드·PR·이슈·Actions 보기) | Contents: Read, Pull requests: Read, Issues: Read, Actions: Read, Metadata: Read |
| PR 만들기·댓글 | 위에 더해 Pull requests: Read and write, Issues: Read and write |
| 에이전트가 `git push` | Contents: Read and write (워크플로 파일을 고치면 Workflows도) |

4. 만든 토큰을 복사해요. GitHub는 이 화면을 떠나면 다시 보여 주지 않아요.

> **참고** 조직이 토큰 승인을 요구하면 조직 관리자가 승인할 때까지 그 조직의 비공개 저장소는 읽지 못해요. 클래식 토큰(`ghp_`)도 되지만 모든 저장소에 넓은 권한을 주게 돼요.

## 계정 연결하기

1. `설정` > `GitHub` > `계정 추가`에서 `토큰으로`를 골라요.
2. `이름 (선택)`에 “회사”, “개인”처럼 알아보기 쉬운 이름을 적어요. 비워 두면 GitHub 아이디가 이름이 돼요.
3. `토큰`에 붙여 넣고 `연결`을 눌러요. own이 GitHub에 "이 토큰은 누구인가요?"를 물어보고, 맞으면 계정이 목록에 생겨요.
4. 쓰기 도구가 필요하면 `쓰기 도구 허용 (쓸 때마다 물어요)`을 켜고 연결하거나, 나중에 계정 줄의 `쓰기 허용`을 눌러요.

- 처음 연결한 계정이 `기본` 계정이 돼요. 다른 계정을 기본으로 하려면 그 줄의 `기본으로`를 눌러요.
- 계정 줄에는 이름, GitHub 아이디, 토큰 종류, 토큰의 마지막 네 글자(`…Ab12`), 기한이 보여요. 토큰 전체는 다시 볼 수 없어요.
- 토큰 기한이 다가오면 새 토큰을 만들어 `토큰 바꾸기…`로 넣어요. 같은 GitHub 사용자의 토큰만 받아요.
- GitHub Enterprise를 쓰면 `GitHub Enterprise 주소 (선택)`에 회사 GitHub 주소를 적어요.

## 브라우저로 로그인 (내 OAuth 앱)

토큰을 직접 만들지 않고 브라우저에서 "허용"만 누르는 방법도 있어요. 다만 GitHub에 **내 OAuth 앱**을 한 번 등록해야 해요. own은 다른 제품(GitHub CLI 같은)의 앱을 빌려 쓰지 않아요.

1. `브라우저 로그인 앱`의 `GitHub에서 OAuth 앱 등록`을 눌러 앱을 만들어요. 이름과 주소는 아무거나 괜찮고, **Enable Device Flow**를 꼭 켜요.
2. 만든 앱의 Client ID를 `Client ID`에 넣고 `저장`을 눌러요. Client ID는 비밀이 아니에요. Client secret은 필요 없어요.
3. `계정 추가`에서 `브라우저로 로그인`을 고르고 `로그인 시작`을 눌러요. 코드가 보이고 GitHub 페이지가 열려요.
4. GitHub 페이지에 코드를 넣고 허용하면 계정이 목록에 생겨요.

> **참고** GitHub 앱(GitHub App)의 Client ID를 넣으면 토큰이 8시간마다 바뀌는데, own이 알아서 새 토큰으로 바꿔요.

## 어디에 어떤 계정: 기본·프로젝트·팀 영역·대화

`어디에 어떤 계정`에서 고르면, own은 이 순서로 계정을 정해요.

1. **대화의 선택**: `이 프로젝트의 대화` 목록에서 대화마다 고른 계정. 그 대화의 하위 에이전트도 같은 계정을 써요.
2. **프로젝트의 선택**: `이 프로젝트의 계정`. 안쪽 폴더에 따로 고른 것이 있으면 그것이 먼저예요.
3. **팀 영역**: 팀 모드의 영역 폴더는 따로 고르지 않으면 본 프로젝트의 선택을 따라요. 영역만 다른 계정을 쓰려면 위의 프로젝트 고르기에서 그 영역 폴더를 골라 계정을 정해요.
4. **기본 계정**: 아무것도 고르지 않은 곳.

- 어떤 프로젝트에서 GitHub를 아예 쓰지 않으려면 `GitHub 끄기`를 골라요.
- 페이지 맨 위의 `지금 이 프로젝트` 줄이 지금 쓰는 계정과 그 이유(`프로젝트 설정`, `기본 계정` 같은)를 보여 줘요. GitHub 도구의 결과에도 계정이 적혀요.

## GitHub 도구와 쓰기 승인

- 도구는 GitHub의 공식 MCP 서버에서 와요. 처음 계정을 연결하면 own이 도구 목록을 읽어 두고, 모든 프로젝트의 대화에서 `github_` 도구로 써요.
- `도구 묶음`에서 쓸 묶음(repos, issues, pull_requests, actions 같은)을 골라요. 많이 켤수록 모델에게 보이는 도구가 늘어요.
- `도구 서버`는 보통 `GitHub가 운영하는 서버` 그대로 두면 돼요. GitHub Enterprise Server를 쓰거나 이 PC에서 돌리고 싶으면 `이 PC의 github-mcp-server`를 고르고 내려받은 프로그램 경로를 적어요.
- 쓰기를 허용하지 않은 계정에는 읽기 도구만 보여요. 쓰기를 허용한 계정도 쓸 때마다 물어요. 내가 만든 에이전트(`opencode.json`의 `agents`나 Markdown 에이전트), 원본 omo의 에이전트에서도 같아요.
- 읽기만 하는 하위 에이전트(`explore` 찾기, `own-review` 리뷰)는 GitHub에 쓰지 않아요. 묻지도 않고 거절하고, 할 일을 메인 대화에 보고해요. `항상 허용`해 둔 쓰기도 이 둘에게는 통하지 않아요. GitHub 읽기(PR·이슈 보기)는 그대로 해요.
- 읽기 도구인지는 GitHub 서버의 표시만 보지 않고 own이 이름까지 확인해요. 애매한 도구는 쓰기로 쳐서 물어요.
- `항상 허용`은 그 계정에만 적용돼요. 다른 계정으로 같은 저장소에 쓰면 다시 물어요.
- `항상 허용`은 저장소 이름이 GitHub에서 쓸 수 있는 이름일 때만 저장돼요. 이름이 이상하거나(`*` 같은) 저장소가 없는 도구는 `저장할 범위가 없어 이번만 허용돼요`라고 나오고 다음에 다시 물어요.
- 저장된 `항상 허용`은 `설정` > `승인·권한`에서 지울 수 있어요. 지우면 다음 쓰기부터 모든 대화에서 다시 물어요(모든 것을 허용한 대화, omo의 하위 대화도).

> **주의** 쓰기 도구는 GitHub에 바로 남아요(PR, 공개 댓글 등). 승인 카드에 적힌 도구 이름과 저장소를 보고 허용해요.

## git push·pull 로그인

- `git 로그인`의 `에이전트·팀 모드의 git push·pull에 고른 계정 쓰기`가 켜져 있으면(기본), 에이전트가 실행한 git과 팀 모드의 `원격 저장소에 올리기…`가 고른 계정으로 GitHub에 로그인해요.
- 대화마다 고른 계정(`GitHub 끄기` 포함)이 그 대화의 git에도 적용돼요. 어느 에이전트 방식이든 같아요.
- **쓰기를 허용하지 않은 계정으로는 push가 안 돼요.** 에이전트의 `git push`도, 팀 모드의 `원격 저장소에 올리기…`도 `github-account-is-read-only` 오류로 멈춰요. push하려면 그 계정의 `쓰기 허용`을 눌러요. clone·fetch·pull은 그대로 돼요.
- 로그인은 그 명령이 도는 동안만 쓸 수 있고, git 자신(이 PC의 git에 든 HTTP 전송과 Git LFS)만 받아요. 에이전트가 같은 주소에 직접 물어도 토큰을 주지 않아요. 명령 승인을 늦게 눌렀거나 명령을 백그라운드로 옮겨도 로그인은 그 명령이 끝날 때까지 돼요(최대 6시간).
- 이 PC의 git 로그인은 Windows에서만 넣어요. 다른 운영체제에서는 git이 내 로그인을 그대로 써요. SSH 원격 호스트(Linux)의 git은 아래 "SSH 원격 호스트에서는" 절처럼 이 PC를 거쳐 가요.
- 로그인할 때마다 어느 계정으로 어느 저장소에 했는지 `own-accounts.log`에 한 줄씩 남아요(`github_git_login`). 토큰은 적지 않아요.
- 도구 결과에 연결한 계정의 토큰이 나오면(셸 출력 같은) 대화에 넣기 전에 `••••`로 가려요. base64로 바뀐 토큰, 백그라운드 명령의 완료 알림, `!` 명령의 출력, 내가 대화에 직접 적은 토큰도 모델에 보내기 전에 가려요. 대화의 모든 모델 요청(대화, 압축, 제목 짓기, 목표 검토·팀 구성 판단 같은 한 번짜리 요청)이 같아요. 지우거나 바꾼 토큰도 30일 동안 계속 가려요(GitHub에서 아직 통할 수 있어서요).
- 이 PC의 다른 터미널에서 내가 직접 실행한 git은 지금처럼 내 Git 로그인(Git Credential Manager 등)을 써요. SSH로 연결한 원격 저장소는 내 SSH 키를 써요.
- 팀 모드의 `검토 요청 올리기…`(gh로 PR 만들기)도 그 영역의 계정으로 만들어요.

> **참고** 이렇게 막아도 에이전트가 git의 통신 자체를 가로채면(인증서 확인을 끄고 자기 프록시를 쓰는 식) 토큰을 볼 수 있어요. 토큰은 쓸 저장소와 권한만 골라 만드는 게 안전해요.

> **주의** own의 **읽기 전용은 단단한 벽이 아니에요.** 실수나 보통의 에이전트는 막지만, 마음먹은 에이전트는 git 설정을 바꿔(`credential.helper` 같은) git이 받은 토큰을 파일로 빼낸 뒤 그 토큰으로 push할 수 있어요. 쓰기를 확실히 막아야 하는 계정은 GitHub에서 **쓰기 권한이 없는 토큰**(세분화 토큰의 Contents: Read 등)으로 만들어 넣어요.

## SSH 원격 호스트에서는

SSH 원격 호스트의 대화에서도 같은 GitHub 연결을 써요. **토큰은 이 PC를 떠나지 않아요.** 호스트는 이 PC에 물어보고, 이 PC가 고른 계정의 토큰으로 GitHub에 대신 보내요.

- **처음에는 읽기만 해요.** 새 호스트는 계정이 쓰기를 허용해도 GitHub를 읽기만 해요(쓰기 도구가 보이지 않고, git push도 멈춰요). 그 호스트에서 쓰려면 호스트의 대화나 프로젝트를 연 채로 `설정` > `GitHub`의 `SSH 호스트의 쓰기`에서 `호스트 …에서 GitHub 쓰기 허용`을 켜요. 허용한 호스트는 같은 곳의 `쓰기를 허용한 호스트` 목록에 보이고, `허용 거두기`로 다시 읽기만 하게 해요. 이 PC의 창에서만 바꿀 수 있어요.
- **도구**: 호스트의 대화에도 같은 `github_` 도구가 보여요. 호출은 이 PC가 실행하고, 결과 맨 위에 쓴 계정이 적혀요. 결과에 연결한 계정의 토큰이 나오면 이 PC에서처럼 가려서 보내요. 쓰기(쓰기를 허용한 호스트에서만)는 이 PC에서처럼 매번 물어요. 승인 카드는 그 호스트의 대화에 떠요.
- **git**: 호스트의 셸에서 에이전트가 실행한 git과 Git LFS의 GitHub 통신은 이 PC를 거쳐 가요. 이 PC가 그 요청에 계정의 로그인을 붙여 GitHub로 보내므로 호스트에는 토큰이 없어요. 쓰기를 허용하지 않은 계정이나 쓰기를 허용하지 않은 호스트에서는 push가 `github-account-is-read-only`로 바로 멈추고, push 주소를 따로 적은 저장소도 이 PC가 거절해요(`403`). GitHub의 답에 로그인(토큰)이 섞여 오면 이 PC가 그 답을 호스트에 보내지 않아요(`502`).
- **어느 계정인지**: 호스트의 대화나 프로젝트를 연 채로 `설정` > `GitHub`을 열면, 맨 위에 `원격 호스트 …의 프로젝트예요` 줄이 보이고 `이 프로젝트의 계정`과 `이 프로젝트의 대화`가 그 호스트의 폴더와 대화를 가리켜요. 순서는 이 PC와 같아요(대화 → 프로젝트 폴더 → 팀 영역은 본 프로젝트 → 기본 계정). 아무것도 고르지 않으면 기본 계정을 써요.
- 어떤 호스트 전체에서 GitHub를 쓰지 않으려면 그 호스트의 맨 위 폴더(`/`)를 프로젝트로 골라 `GitHub 끄기`를 골라요.
- 이 PC와 호스트가 연결돼 있어야 해요. 연결이 끊기면 GitHub 도구는 `could not reach the PC's GitHub connection` 오류를 내고, git은 호스트 자신의 로그인을 써요.
- 호스트의 `gh`(GitHub CLI)는 이 PC의 토큰을 받지 않아요. 호스트에서 PR을 만들 때는 GitHub 도구(`create_pull_request`)를 써요.
- 호스트에서 내가 직접 연 터미널의 git, 다른 사용자의 프로그램은 이 PC를 거치지 않아요. 이 PC를 거치는 것은 own 서비스가 실행한 git과 Git LFS뿐이에요. 한 명령에 준 로그인은 그 명령(과 그 명령이 띄운 프로그램)만 써요. 다른 명령이 가져다 쓰면 거절해요.

> **참고** 호스트에 토큰은 없지만, 명령이 도는 동안에는 그 명령의 git이 이 PC를 거쳐 그 계정으로 GitHub에 닿을 수 있어요. 호스트를 믿을 수 없으면 쓰기를 허용하지 말고, 그 호스트는 `GitHub 끄기`로 두거나 읽기만 하는 토큰의 계정을 골라요.

## 문제가 생기면

| 증상 | 할 일 |
|---|---|
| 계정 줄에 `GitHub가 토큰을 받지 않아요` | 토큰이 지워졌거나 기한이 지났어요. 새 토큰을 만들어 `토큰 바꾸기…`로 넣어요 |
| 도구가 안 보여요 | `도구` 줄을 확인하고 `도구 다시 읽기`를 눌러요. 그 프로젝트에 계정이 없거나 `GitHub 끄기`면 도구가 없어요 |
| 쓰기 도구가 "읽기만 허용" 오류를 내요 | 그 대화가 쓰는 계정의 `쓰기 허용`을 눌러요 |
| 비공개 저장소가 안 보여요 | 세분화 토큰의 Repository access에 그 저장소가 있는지, 조직 승인이 끝났는지 확인해요 |
| push가 로그인에서 실패해요 | 토큰에 Contents: Read and write가 있는지, `git 로그인`이 켜져 있는지 확인해요 |
| push가 `github-account-is-read-only`로 멈춰요 | 그 폴더·대화가 쓰는 계정이 읽기만 해요. 계정 줄의 `쓰기 허용`을 눌러요 |
| `항상 허용`했는데 또 물어요 | 저장소 이름이 이상한 요청이었거나, 다른 계정으로 쓰는 중이거나, `설정` > `승인·권한`에서 지웠거나, 이 기능 전에 저장한 허용(계정이 없는 옛 형식)이에요. 다시 `항상 허용`을 눌러요 |
| 리뷰 탭의 git이 로그인하지 않아요 | 그 폴더의 대화 중 하나가 지난 7일 안에 다른 계정이나 `GitHub 끄기`를 골랐어요. 그 대화의 계정 선택을 지우거나 리뷰 탭 대신 그 대화에서 실행해요 |
| 다른 git 프로그램(포터블 git 등)으로는 로그인이 안 돼요 | own은 이 PC에 설치된 Git for Windows의 git과 Git LFS에만 로그인을 줘요 |
| 원격 호스트에서 GitHub 도구가 안 보여요 | 이 PC와 호스트가 연결돼 있는지(`설정` > `원격 호스트`), 이 PC와 호스트가 같은 버전인지 확인해요. 그 호스트 폴더에 `GitHub 끄기`를 골랐는지도 봐요 |
| 원격 호스트에서 쓰기 도구가 안 보여요 | 그 호스트에 쓰기를 허용하지 않았어요. `설정` > `GitHub`의 `SSH 호스트의 쓰기`에서 그 호스트를 허용해요(계정의 `쓰기 허용`도 켜져 있어야 해요) |
| 원격 호스트의 git이 `403`이나 `github-account-is-read-only`로 멈춰요 | 읽기만 하는 계정이거나 쓰기를 허용하지 않은 호스트에서 push했어요. 그 계정의 `쓰기 허용`과 `SSH 호스트의 쓰기`의 그 호스트를 켜요 |
| 원격 호스트의 git이 `502`로 멈춰요 | GitHub의 답에 로그인이 섞여 와서 이 PC가 막았어요. 다시 해도 같으면 `own-accounts.log`의 `github_answer_refused` 줄을 확인해요 |
| 원격 호스트의 git이 `503`으로 멈춰요 | 호스트가 이 PC에 닿지 못해요. 연결이 돌아오면 다시 실행해요 |
