# own-open-code 사용 설명서

이 폴더는 own-open-code 데스크톱 앱의 사용 설명서예요. 장마다 Markdown 파일이 하나씩 있고, 화면 사진은 `images/`에 있어요. 이것을 모두 묶은 **파일 하나짜리 HTML**이 [own-open-code-manual.html](own-open-code-manual.html)이에요.

## 읽기

- `own-open-code-manual.html`을 파일 탐색기에서 두 번 누르면 브라우저로 열려요. 서버도 인터넷도 필요 없어요. 그림까지 파일 안에 들어 있어서 다른 PC나 휴대폰으로 옮겨도 그대로 열려요. (장 끝의 설계 문서 링크만 이 저장소 안에서 열 때 열려요.)
- 왼쪽 목차(좁은 화면에서는 왼쪽 위 단추), 위쪽 검색 상자(`/` 또는 `Ctrl+K`), 어둡게·밝게 단추가 있어요. 그림을 누르면 크게 보여요. 인쇄하면 밝은 색으로 장마다 새 쪽에 나와요.
- 처음 테마는 컴퓨터 설정을 따라요(밝게가 아니면 어둡게). 단추로 고른 테마는 그 브라우저에 기억돼요.
- 화면 사진 속 계정, 대화, 폴더 경로(`D:\demo\space-game`)는 모두 가짜 데모 데이터예요. 숫자(한도 %, 금액)는 예시예요.

## HTML 다시 만들기

저장소 루트에서 실행해요. Bun만 있으면 되고, 더 설치하거나 내려받는 것은 없어요.

```powershell
bun own/scripts/manual/build-html.ts
```

생성기(`own/scripts/manual/build-html.ts`)가 하는 일:

1. 이 폴더의 `NN-*.md`를 파일 이름 순서대로 읽어요. `PLAN.md`와 이 `README.md`는 HTML에 넣지 않아요. `00-index.md`가 있으면 그 내용이 표지가 되고, 없으면 생성기가 표지를 만들어요.
2. Bun에 들어 있는 Markdown 변환기(`Bun.markdown`)로 HTML을 만들어요.
3. 그림은 `data:` 주소로 파일 안에 넣고, 스타일(`html/manual.css`)과 스크립트(`html/manual.js`)도 안에 넣어요. 그래서 바깥에서 불러오는 것이 하나도 없어요.
4. 아래 검사를 하고, 통과하면 `own-open-code-manual.html`을 쓰고 위의 장 목록을 고쳐요.

| 검사 | 걸리면 |
|---|---|
| 그림 참조가 모두 있는 파일을 가리키는지 | 실패 (`--allow-missing`이면 점선 상자로 대신) |
| 어느 장에서도 안 쓰는 그림 | 경고 |
| 페이지가 네트워크에서 무엇이든 불러오는지 (`src`, `href`, CSS `url()`) | 실패 |
| HTML 크기 25 MB 이하 | 실패 |
| 그림 한 장 350 KB 초과 | 경고 |
| 개인정보: 이 PC의 사용자 이름·PC 이름, 데모가 아닌 사용자 폴더, 앱 데이터·임시 폴더 경로, 실제 이메일 주소 | 실패 |
| 백틱 안 한글 라벨이 앱의 실제 문자열(own-web, own-desktop, Android)에 있는지 | 경고 (`--strict`면 실패) |
| 아직 없는 장으로 가는 링크 | 경고 (HTML에서는 링크 없는 글자로 보여요) |

| 옵션 | 뜻 |
|---|---|
| `--check` | 검사만 하고 아무 파일도 쓰지 않아요 |
| `--allow-missing` | 없는 그림을 실패 대신 "스크린숏 준비 중" 상자로 보여요 |
| `--strict` | 라벨 경고도 실패로 봐요 |
| `--out <file>` | 다른 곳에 HTML을 써요 |

라벨 검사에서 일부러 쓰는 개념어(앱 문자열이 아닌 것)는 `own/scripts/manual/labels-allow.txt`에 한 줄에 하나씩 적으면 빠져요. 이 파일은 필요할 때만 만들어요.

### 브라우저로 확인하기

```powershell
bun own/scripts/manual/check-html.ts
```

설치된 Microsoft Edge를 Playwright로 띄워(헤드리스) HTML을 `file://` 주소로 열고 확인해요. 네트워크 요청이 하나도 없는지(오프라인에서도 열리는지), 어두운·밝은 테마의 처음 값과 단추, 1440 폭과 375 폭에서 가로 스크롤이 없는지, 좁은 화면의 목차 서랍, 검색(결과 → 해당 절로 이동 → 낱말 표시), 그림 확대와 닫기, 읽는 곳 따라가는 목차, 인쇄 화면을 봐요. `--shots <폴더>`를 주면 확인한 화면을 PNG로 남겨요(커밋하지 않는 폴더로).

## 고치거나 더할 때

글쓰기 규칙 전체는 [PLAN.md](PLAN.md) §2에 있어요. 생성기가 기대하는 모양만 추리면 이래요.

- **장 파일**: `NN-slug.md`(영문 파일 이름). 첫 줄은 `# N. 제목`, 그다음 단락은 `**한 줄 요약**: …`. 번호로 부가 정해져요: 00–05 1부, 06–10 2부, 11–21 3부, 22–25 4부, 26–29 5부, 90 이상 부록.
- **화면 문구**: 앱에 보이는 그대로 백틱 안에 써요. 한글이 든 백틱은 화면 문구로 보고 검사해요. 그래서 예시 문장이나 강조에는 “따옴표”를 써요. 메뉴 길은 한 단계에 백틱 하나씩 써요(설정 > 일반처럼 한 백틱에 몰지 않기).
- **단축키**: `Ctrl+Shift+U`처럼 쓰면 HTML에서 키 모양으로 보여요.
- **상자**: `> **팁** …`, `> **주의** …`, `> **용어** …`, `> **참고** …`는 색 상자가 돼요.
- **그림**: `![대체 글](images/<id>.webp "캡션")`을 한 단락에 혼자 두면 캡션이 달린 그림이 돼요. 1440×900 전체 화면 사진은 그대로, 나머지(2배로 찍은 잘라 낸 사진)는 절반 크기로 보여요. 누르면 원래 크기로 볼 수 있어요.
- **설명 그림**: 장 안에 `<figure class="diagram">`과 인라인 SVG로 넣거나, `diagrams/<id>.svg`를 그림처럼 참조해요(HTML 안에 그대로 들어가요). 색은 `currentColor`를 써야 두 테마에서 다 보여요. 캡션은 “그림:”으로 시작해 실제 화면이 아님을 밝혀요. 휴대폰에서도 읽히게, 넓은 그림(`<svg class="dg-wide">`, 폭 680 안팎)과 위아래로 쌓은 좁은 그림(`<svg class="dg-narrow">`, 폭 320)을 한 figure에 함께 넣어요. 640px 아래에서는 좁은 그림만, 인쇄할 때는 넓은 그림만 보여요. figure 안에는 빈 줄을 두지 않아요(빈 줄이 있으면 Markdown이 HTML 덩어리를 끊어요). 고정 폭 글꼴로 줄을 맞춘 글 그림(```text)은 한글 폭이 맞지 않으니 쓰지 않고, 화면에 보이는 한 줄을 그대로 옮길 때만 써요.
- **장 사이 링크**: `[11장](11-cache-switch-cost.md)`처럼 파일 이름으로 걸면 HTML에서는 페이지 안 링크가 돼요.

## 화면 사진 다시 찍기

`own/scripts/manual/capture.ts`가 가짜 프로바이더와 가짜 계정만 있는 데모 환경을 띄우고, 설치된 Edge로 화면을 찍어 `images/<id>.webp`로 저장해요. 실제 계정·대화·설정은 건드리지 않아요. 화면의 경로는 데모 경로로 바꿔 찍고, 이 PC의 사용자 이름이나 임시 폴더가 보이는 사진은 저장하지 않아요. 쓰는 법은 그 파일 맨 위 주석과 [PLAN.md](PLAN.md) §4–§7에 있어요. 사진을 바꾼 뒤에는 HTML을 다시 만들어요.
